# 배경 접합 수정과 확인

탐색 복도 원경·수목을 늘릴 때 실내 창문과 같은 위치에서 잘라 붙여 창 안에 수직 경계가 생겼다. 원경의 오른쪽 1044px은 비어 있었다. 동일한 붙임 위치에서 바닥의 사선 햇빛과 대리석 무늬도 잘렸다.

## 수정

- 원경·수목: 원래 끝의 동일한 픽셀을 공유하는 반사 연장으로 전체 폭을 채웠다. 앞 2172px 원본은 그대로 보존했다.
- 바닥: 생략됐던 앞쪽 바닥 24열을 겹쳐 넣고 불규칙한 경계로 연결했다. 원화 x2088~2171, y436~723 안의 888논리 도트만 바뀌었다. 빛무늬를 반전하거나 새 색을 섞지 않았다.
- 게임용 복도 PNG 3종, Authored/Runtime/Preview, 3레이어 Aseprite 원본을 갱신했다. 모든 메타데이터와 다른 배경 45개 PNG/메타는 기존 해시와 일치한다. 창문·벽·패널·문·바닥의 나머지 영역도 기존 픽셀과 같다.
- 재생성 시 같은 문제가 생기지 않게 `../build_corridor.py`의 결합 규칙과 `../verify_scenery_joins.py` 검증을 추가했다.

## 결과

`window-before-after.png`와 `floor-before-after.png`는 동일 카메라의 실제 Unity 렌더를 같은 좌표로 잘라 비교한 판이다. `before/after-corridor.png`, `before/after-floor.png`, `before/after-corridor-wide.png`에 전체 캡처를 보관한다.

Unity 6000.5.9f1 / D3D11에서 수정 전후 각 15장을 렌더했다. 최종 15장 모두 빈틈이 없었고 숲 6장·전투 복도 3장은 전후 픽셀이 동일하다. 창 안의 수직 경계와 바닥의 잘라붙임이 사라진 것을 확인했다. 검증은 실제 배경 표시 클래스와 기존 PNG·임포트 설정을 복사한 격리 프로젝트의 Built-in 스프라이트 렌더이며, 본 프로젝트 전체 URP·게임 UI·플레이어 빌드는 포함하지 않는다. 상세 명령과 범위는 `Unity-validation.md`, 수치는 `Unity-summary.json` 및 `render-summary.json`, 검증용 원본은 `BackgroundLoopRenderValidation.cs`에 있다. 이 C# 파일은 Docs에만 보관하며 게임에 포함되지 않는다.

## 원본과 보존 확인

`audit-summary.md`는 현재 사용하는 배경 전반의 반복 방식과 수정 범위를 기록한다. `baseline-resources.json`과 `final-preservation-check.json`은 다른 배경·메타데이터 보존 및 바닥 수정 범위를 확인한 기록이다. `resource-comparison.json`은 창밖 두 레이어의 접합 전후 수치다.

Aseprite로 저장한 원본을 다시 열어 3레이어 각각이 Authored PNG와 픽셀 단위로 일치함을 검사했고, 별도 CLI로 다시 연 합성 출력도 최종 합성 PNG와 일치했다. 배치 실행은 이 검사를 통과한 뒤 네이티브 종료 코드 -1073740791을 반환했으므로 정상 프로세스 종료까지 성공했다고 주장하지 않는다. 편집 원본의 저장·재열기·픽셀 일치는 별도로 확인됐다.
