# 탐색 필드 배경 리소스

학교 복도와 바깥 숲을 한정된 벨트 스크롤 공간으로 그린 리소스다. 기존 전투 배경은 그대로 두고, 탐색 필드에서 사용할 별도 이미지로 보관한다.

| 공간 | 편집 원본과 미리보기 | 게임용 레이어 |
| --- | --- | --- |
| 학교 복도 | `Corridor/` | `Assets/Game/Resources/ExplorationMaps/Corridor/` |
| 바깥 숲 | `Forest/` | `Assets/Game/Resources/ExplorationMaps/Forest/` |

각 공간은 가로 4096px, 기본 그림 높이 724px으로 제작한다. 도트 작업 원본은 가로 1024×세로 181픽셀이고, 게임 PNG는 최근 전투 배경과 같은 4배 격자다. 복도 게임용 레이어에는 위 160px, 아래 32px의 여백을 더해 4096×916px로 내보낸다. 따라서 복도의 원본 y좌표는 게임용 PNG에서 y+160px이 된다. 모든 레이어는 같은 캔버스·기준점을 공유하고, 창밖이나 먼 숲의 레이어만 시차 이동에 쓸 수 있다.

복도 오른쪽에는 출구로 읽히는 문과 벽면을 둔다. 숲 왼쪽에는 나무 사이의 입구와 그 너머에 멀리 보이는 학교를 둔다. 두 그림은 각각 완결된 장면이며, 출입문이나 석재 바닥을 서로 복사해 맞추지 않는다. 각 장면의 지면과 가까운 입구 표식은 고정 레이어에 있고, 먼 배경은 별도 레이어로 정리한다. 두 PNG 세트의 끝부분은 타일 반복을 전제로 그리지 않았다.

필드에서 쓰는 상호작용 기준 좌표는 아래와 같다. 그림의 왼쪽 위가 (0, 0)이며, 복도의 게임용 PNG에서는 y에 160px을 더한다. 숲의 기준점은 먼 학교 건물 자체가 아니라 앞쪽 입구를 나타낸다.

| 공간 | 필드 상호작용 기준 x | 그림에서 보이는 표식 |
| --- | ---: | --- |
| 복도 오른쪽 | 약 3720px | 출구 문과 문 앞 바닥 |
| 숲 왼쪽 | 약 352px | 나무 사이 입구와 멀리 학교로 이어지는 길 |

`Package-For-Unity.ps1`을 실행하면 각 폴더의 `Runtime/` PNG를 `Assets/Game/Resources/ExplorationMaps/` 아래로 복사한다. 새 이미지에는 기존 전투 배경과 같은 128 PPU, Point 필터, Full Rect, 밉맵·압축 끔, 최대 4096px의 Unity 임포트 설정을 붙인다. 재실행 시 이미 생성된 메타데이터 GUID는 유지한다.

이 폴더에는 그림과 패키징만 포함한다. 캐릭터 이동, 문 전환, 카메라 범위, 필드 배경 표시 방법은 필드 구현에서 연결한다.

## 게임 내 연결

`ExplorationFieldBackdrop`이 위 게임용 레이어를 탐색 필드에 표시한다. 각 레이어는 한 장씩 배치하며, 문·바닥·숲 전경은 고정하고 먼 풍경에 시차를 준다. 724px 높이를 12.4 월드 단위로 맞추고 원화 중앙을 `(0, -1.5)`에 놓는다. 복도의 추가 여백은 이 기준을 유지하도록 보정한다. 카메라는 유한한 맵 가장자리를 넘지 않는다.

`AcademyFieldView`에서 복도 오른쪽 문과 숲 왼쪽 문에 가까이 가서 Space 또는 클릭하면 약 0.5초의 암전과 함께 반대편 문으로 이동한다. 문턱 원화 y=488px을 발높이 기준으로 사용하며, 이동 중 입력은 잠시 멈춘다. 숲 오른쪽에서는 철책 앞에 이동 경계를 둔다.

필드 이동은 WASD다. 2026-10-14부터 기본 속도는 4.5에서 6 월드 단위/초로 올렸고, 왼쪽 또는 오른쪽 Shift를 누른 동안 1.5배(9 단위/초)로 달린다. 대각선은 방향을 정규화해 같은 속도를 유지한다. 달릴 때만 캐릭터의 현재 프레임을 옅은 잔상으로 남긴다. 잔상은 0.06초 간격, 초기 불투명도 22%, 수명 0.18초이며 기존 잔상 풀 5개를 재사용한다. 멈추거나 걸으면 자연스럽게 사라지고, 메뉴·필드 숨김·맵 전환 때는 바로 정리한다. 벽에 막혀 실제로 움직이지 않을 때도 잔상을 만들지 않는다.

2026-10-14 검증: 변경 전 필드 검사 5개, 변경 후 기존 검사와 달리기 회귀 검사 총 8개가 모두 통과했다. Unity 컴파일 오류 0개이며, 별도 D3D11 실행의 1600×900 캡처에서 엘리사 뒤의 옅은 잔상 3개도 확인했다. 검사 기록은 `Logs/FieldRunPlayModeFinal-20261014.xml`(필드 8개 + 임시 화면 캡처 1개), 그림은 `Logs/FieldRunVisual-20261014.png`이다. 캡처용 코드는 검증 사본에서만 사용하고 제거했다.

기존 전투 NPC·스토리 게시판·수련 허수아비는 복도에 있다. 바깥 숲 길에는 임시 테스트용 기술 습득물 네 개가 떠 있다(`Docs/FieldPickups.md`). 전투·스토리·메뉴를 마친 뒤에는 같은 맵과 캐릭터 위치로 돌아온다. NPC는 필드에 다시 들어올 때 재배치된다. 탐색 위치는 현재 플레이 동안만 유지되며, 타이틀의 이어하기는 복도 입구에서 시작한다.

2026-10-13 검증: 별도 Unity 프로젝트에서 `AcademyFieldViewPlayModeTests` 3개 모두 통과했다. WASD·게시판, Space/클릭 문 왕복, 거리 제한, 전환 중 입력 차단, 맵·위치 유지와 초기화를 검사했다. 결과는 `Logs/ExplorationMapsPlayModeResults.xml`에 보관한다. 그래픽 없이 실행한 검증이며, 실제 화면 육안 검수와 플레이어 빌드는 포함하지 않는다.
