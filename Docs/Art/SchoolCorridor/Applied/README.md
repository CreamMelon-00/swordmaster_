# 학교 복도 적용판

서막 전투(임무 1~4)는 새벽 숲을 유지하고, 이후 전투(임무 5~9 및 일반 전투)에는 이 학교 복도를 사용한다. 원본은 `../Concepts/yellow-stone-corridor-v3.aseprite`, 게임에서 읽는 파일은 `../../../../Assets/Game/Resources/SchoolCorridor/`에 있다. 게임의 세 레이어는 `Runtime/`에 보관한 상하 여백 포함 판과 동일하고, 로비/브리핑 합성본은 이 폴더의 원래 2172×724 구도다.

| 파일 | 용도 |
| --- | --- |
| `corridor-far.png` | 창밖 먼 하늘과 교정, 불투명 원경 |
| `corridor-near.png` | 창밖 앞쪽 수목, 투명 근경 |
| `corridor-interior.png` | 창틀·석조 벽·가스등·바닥, 창 유리는 투명 |
| `corridor-composite.png` | 브리핑과 미리보기용 합성본 |

각 PNG와 같은 이름의 `.aseprite` 편집본을 보관한다. Aseprite로 543×181 픽셀에서 4배 확대한 2172×724 PNG이며, 세 레이어는 동일한 프레임을 공유한다. 64색 이내 팔레트, 4×4 픽셀 격자, 투명도 0/255만 사용한다. 게임 레이어의 Unity 임포트는 128 PPU, Point 필터, Full Rect, 밉맵·압축 꺼짐이다.

창밖 레이어는 승인 시안보다 원경과 근경을 각각 40px 위로 올렸다. 전투 카메라와 캐릭터 발 위치에 맞춰 벽/바닥 경계를 원본 y=528에서 적용판 y=432로 조정했다. `../Tools/reframe_layers.lua`가 해당 세 레이어를 같은 규칙으로 변환하고, `../Tools/compose_applied.lua`가 합성본을 만든다. 변환 확인 결과는 `reframe-verification.txt`에 기록했다.

와이드 화면에서 카메라가 기울어져도 배경 가장자리가 노출되지 않도록 `../Tools/pad_runtime_layers.lua`가 세 게임 레이어에 위 160px·아래 32px의 도트 여백을 더한다. `Runtime/`의 출력은 2172×916이며, 원래 그림은 y=160~883에서 픽셀 그대로 보존된다. 월드 높이 15.68839779, 중심 Y=-0.4038674로 배치하면 원래 그림의 크기와 바닥 경계(Y≈-2.699)가 유지된다. 결과는 `Runtime/padding-verification.txt`에 기록했다.

게임 화면에서 캐릭터가 바닥 뒤쪽 벽에 너무 가까워 보였다. 복도 전투와 복도 컷신의 캐릭터 루트만 숲의 Y=-0.5보다 0.95 낮은 Y=-1.45로 조정했다. 일반 전투의 넓은 화면에서는 카메라 목표를 0.95 올려 기존 배경 구도를 유지하고, 가까운 전투 화면에서는 보정을 0.7로 줄여 그림자가 화면 아래에서 잘리지 않게 한다. 인물 확대 시에는 보정을 더 줄여 전신을 따라간다. 그림자는 캐릭터 자식이므로 함께 움직이며, 숲의 위치와 배경 PNG는 변경하지 않는다.
