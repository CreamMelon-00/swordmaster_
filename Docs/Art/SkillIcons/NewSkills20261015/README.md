## 파일과 제작

`GroupA`, `GroupB`, `GroupC`의 `Generated/`는 내장 imagegen으로 각 아이콘을 따로 제작한 원본이다. 같은 그룹의 `prompts.json` 또는 `prompts.md`에 사용한 전체 프롬프트와 수정 기록을 저장했다. 기존 통일 아이콘을 스타일 참고로 사용했고, 새 일반 스킬에 적 전용 금빛 연출을 적용하지 않았다.

각 그룹의 `48/`는 투명도0/255, 최대48색, 보이는 외곽44px 이하로 정리한 생성 초안이다. `Runtime192/`는 최근접4배 출력이다. 생성 문양을 기존 통일본의 격자·팔레트·정렬에 맞추고, 최종 수정에서 기존 프레임과 승인된 검 픽셀을 조합했다.

생성 초안은 계열 이름과 크기를 맞춰도 기존 그림과 프레임 두께·모서리·배경 명암이 달랐다. 사용자 검토 뒤 `StyleRefinement/`에서 기존 참격10·관통4·타격5·방어15의 실제 프레임과 가죽 바탕을 기준으로 재정리했다. 큰 효과보다 검 한 자루와 주요 동작이 먼저 읽히게 문양 크기·강철 색도 맞췄다. 꿰뚫기23과 받아치기24는 생성된 중심 문양이 가늘고 어두워, 최종본에 기존4·5의 실제 검 픽셀을 원래 굵기와 밝기로 사용했다. `CenterRefinement/`에는 총신처럼 보이던 찌르기, 과한 접촉 섬광, 검보다 큰 순환/호흡 부호를 보완한 창작 입력을 보관한다. `StyleRefinement/48/`가 있으면 최종 집계와 게임 적용은 이 수정본을 사용한다.

`assemble.py`는 최종 결과를 검증해 `Output/48/`, `Output/Runtime192/`, 이름이 붙은 `Output/new-skills-preview.png`, 기존4계열과 비교하는 `Output/style-review.png`, 실제48px `Output/contact-48-native.png`와 `Output/manifest.json`을 만든다. `--apply`를 주면 새15개 PNG만 `Assets/Game/Resources/SkillRoles/role21.png`~`role35.png`로 복사하고 새GUID의 Point/Clamp/무압축/밉맵끔/중앙pivot/FullRect 메타데이터를 붙인다. 이후 재적용은 이미 만든 GUID를 유지한다. 기존1~20 그림과 메타는 `baseline-existing-runtime.json`의 해시로 변경되지 않았는지 확인한다.

게임의 `LegacyDuelArt.SkillIconCount`는35이며, `Skills/skills.csv`의 대상15행의 그림 번호가21~35를 가리킨다. 전투·편성·커리큘럼·필드 습득 화면 모두 같은 `skill.IconId`를 사용한다.

`build_and_verify_master.lua`는 15개 논리PNG를 한 프레임씩 넣고 `role21`~`role35` 태그가 있는 `NewSkillIcons-48.aseprite`를 만든 뒤, 다시 열어 각 프레임이 PNG와 픽셀 완전히 동일한지 검사한다. 기존 통일20종의 Aseprite 마스터는 별도로 유지한다.

## 재생성

프로젝트 루트에서 번들 Python으로 `assemble.py`를 실행한다. 그룹 원본을 다시 처리해야 한다면 각 그룹의 제작 스크립트를 먼저 실행한다. `assemble.py --apply` 뒤 Aseprite를 아래처럼 호출한다.

```powershell
& 'C:\Users\User\Desktop\Aseprite\Aseprite.exe' -b --script-param 'root=C:/Users/User/Documents/swordmaster_' --script 'Docs/Art/SkillIcons/NewSkills20261015/build_and_verify_master.lua'
```

## 확인 범위

논리48px·게임192px, 외곽44px, 이진 투명도, 최대48색, 최근접4배, 서로 다른15개 그림, 스킬 시트의 번호와 게임용 파일의 일치를 확인한다. 작은 크기에서 검·숫돌·발걸음과 역할별 외곽을 확인했다. 구체적인 실행 결과는 `validation.txt`에 기록한다.

Aseprite 배치 실행은 저장·재열기 검사 후 네이티브 종료 코드 -1073740791을 반환했다. 별도 CLI 실행으로 원본을 다시 열어 PNG/JSON을 출력했고, 15프레임의 픽셀과 15태그가 최종 PNG와 모두 일치함을 확인했다. 독립 출력에는 `--list-tags` 옵션을 사용한다. Unity 에디터에서 실제 화면을 띄운 확인은 이번 검증에 포함하지 않았다.
