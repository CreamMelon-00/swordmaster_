## 기존 양식 유지

`References/CleanBases/`는 이전 승인본의 참격·관통 빈 프레임을 바이트 그대로 복사한 파일이다. 테두리·가죽 바탕을 생성 모델에 다시 그리게 하지 않았다. 새 문양은 중심 편집 마스크 안에 배치하고 나머지 모든 픽셀은 빈 프레임과 RGBA가 동일한지 검사한다. 원래 검의 손잡이·검끝이 남아 있는 raw role4에서 프레임을 다시 추출하지 않는다.

48×48 논리 도트, 보이는 외곽 최대44×44, 이진 투명도, 불투명 색48개 이하를 유지한다. 게임 PNG는 보간 없는 최근접4배인192×192다. 생성 문양의 강철·잉크·청록·올리브색은 승인된 기존 리소스의 팔레트로 정리한다. 일반 기술에 적 전용 황금 후광을 사용하지 않는다.

돌파·연습 반격의 첫 대각 구도는 마름모 안에서 너무 작아져 검이 약하게 보였다. 위·아래로 긴 세로 구도로 다시 생성해 기존 크기에서 읽히게 했으며, 잘라서 프레임에 억지로 넣지 않았다. 최종 네 문양 모두 프레임에 잘린 픽셀은0개다. 첫 시안은 `Generated/Initial/`에 보관한다.

## 파일과 제작 경로

- `Generated/role36.png`~`role39.png`: **내장 image_gen**으로 각각 생성한 투명 중심 문양. CLI/API 대체 경로를 사용하지 않았다.
- 전체 프롬프트: `Prompts/role36.md`, `Prompts/role39.md`, `Prompts/role36-revision1.md`, `Prompts/role39-revision1.md`, `Generated/prompts-agent-37-38.json`. 최종36·39는 revision1 편집 프롬프트를 사용한다.
- `Output/Symbols48/`: 격자·팔레트를 맞춘 투명 중심 문양.
- `Output/48/`: 기존 프레임과 결합한 최종48px 그림.
- `Output/Runtime192/`: 게임용192px PNG.
- `Output/new-skills-preview.png`: 같은 배율의 기존 기준/신규4종 및40·44·48px 판독 비교.
- `Output/new-icons.png`: 최종4종 이름이 붙은 확대 미리보기.
- `Output/actual-48px.png`: 실제48px 크기 모음.
- `Output/manifest.json`: 배치·색상·프레임 검사와 적용 여부.
- `NewSkillIcons-48.aseprite`: 4프레임, role36~39 태그. **기존 프레임/가죽과 새 문양을 별도 레이어**로 편집할 수 있다.

`build_icons.py`는 생성 문양의 미세 투명도 흔적을 정리하고, 기존 도트 팔레트에 맞춰 빈 프레임 안에 배치한다. `--apply`는 새4개 PNG와 최초 생성하는 메타만 게임 폴더에 넣고, 대상4행의 그림 번호 및 `LegacyDuelArt.SkillIconCount`를39로 연결한다. 다시 적용해도 GUID는 유지한다. `baseline-existing-art.json`으로 기존35종과 그 원본·메타92개가 그대로인지 확인한다.

프로젝트 루트에서 번들 Python으로 `build_icons.py --apply`를 실행한 뒤 Aseprite 배치에서 `build_master.lua`를 실행한다. 스크립트 인자 `root`에는 이 아트 폴더의 절대 경로를 전달한다. 별도 Aseprite `--list-tags --sheet --data` 내보내기의 출력은 `Temp/SkillIconsBuild20261018/master-export.png` 및 `.json`에 놓고 `verify_master.py`로 검증한다.

- 기존35종과 관련 원본·메타92개 해시 동일. 새 프레임의 보호 픽셀 불일치0개.

- Aseprite 저장·재열기 검사와 독립 CLI 출력에서 최종4프레임·4태그가 PNG와 일치했다. 네이티브 종료 코드 -1073740791은 저장/내보내기 뒤 반환됐다. 정상 종료를 주장하지 않으며 파일 내용은 별도 검증했다.

독립 검토에서40~48px 가독성, 검 잘림·프레임 충돌·흐림·깨진 효과를 점검해 적용을 막는 문제를 찾지 못했다.
