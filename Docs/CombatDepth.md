# 전투의 앞뒤 동선과 바닥 표시

2026-10-18 갱신. 전장 바닥의 실제 XY 위치와 속도로 동선을 계산한다. 접근할 상대, 받은 밀림, 회피 입력과 남은 관성에서 이동이 생긴다. 이동 조작을 추가하지 않고 캠페인과 대전에 같은 표시를 사용한다.

## 동선

| 구간 | 움직임 |
|---|---|
| 편성 | 전투의 불릿타임에서는 서로 천천히 다가가며 최소 간격에서 멈춘다. 너무 가까이 시작하면 먼저 물러서고, 넘기기에는 더 빨리 다가간다. Y 방향의 임의 왕복이나 고정 높이 목표는 만들지 않는다. 결투의 편성은 기존처럼 서 있는다. |
| 접근·추격 | 현재 상대와의 가로 교전 거리만 좁힌다. 각자 서 있는 Y는 유지하고 남은 세로 관성만 감속한다. 가속해서 출발하고 목표에 가까워지면 감속하며, 이미 들어온 거리를 넘어서 지나가지 않게 한다. |
| 타격·방어 | 현재 두 사람을 잇는 방향으로 밀림을 계산한다. 피해·방어에 따른 기존 밀림 크기는 유지하고, 그림에 맞도록 세로/가로 기울기는 0.35 이내로 제한한다. |
| 회피 | 기존 뒤로 물러서는 이동에 최대0.28의 옆 디딤을 더한다. 한 기술의 첫 수동 성공은 뒤로 이동하는 거리와 옆 디딤을1.45배로 늘려, 옆으로는 최대0.406 디딘다. 위·아래 방향을 회피마다 번갈아 선택하며, 경계에서 해당 걸음을 충분히 디딜 수 없으면 공간이 넓은 안쪽을 선택한다. 거리와 방향은 회피 시작 때 고정하고 실제 이동한 방향을 기준으로 다음 방향을 정한다. 끝난 뒤 그 자리를 유지하며, 기술·턴 전환은 방향 순서를 초기화하지 않는다. 압박에는 옆 디딤을 더하지 않고 방향 순서도 소비하지 않는다. |
| 턴 정리 | 남은 관성을 감속하고 현재 위치를 다음 편성으로 이어 간다. 기술·턴 경계에서 시작점이나 지정된 높이로 복귀시키지 않는다. |

여기서 앞뒤는 화면의 Y 방향이다. 화면 아래쪽에 있는 사람이 앞에 보인다. 기술의 몸체 돌출은 그림에 적용하는 별도 효과라 실제 바닥 위치와 구분한다. 성공 스텝·붕괴·강타·마무리의 슬로모션에서는 플레이어 공격 그림만 실제 시간으로 부드럽게 최대1.7배 돌출된다. 적과 실제 바닥 위치·사거리·밀림 목표·타격 시각은 그대로다. 힘겨루기는 확대량을 고정하고 컷신 중에는 숨긴 채 멈췄다가 복귀한다. 스텝의 실제 이동 확대와 공격 그림 확대는 `LegacyArenaView.SlowMovement.cs`가 맡으며, 슬로모션 지속시간은 늘리지 않는다.

복도 전장은 앞뒤 범위 전체가 바닥 안에 있도록 중심 루트를Y=-2.30으로 둔다(기존-1.45에서0.85 하강). 실제 발 중심은-4.53이고 허용 범위는-5.73~-3.33이다. 가장 뒤에 선 캐릭터의 발과 원도 벽·바닥 경계 약-2.70 아래에 남는다. 초기 배치·회피·밀림·퇴장이 같은 중심을 쓰며, 카메라는 기존 HUD 바닥과 바닥 원 여백을 따른다.

이전의 편성 ±0.45·기술별 ±0.28 고정 목표는 사용하지 않는다. 움직임은 가속 0.10초·제동 0.08초 기준으로 계산하며, 짧은 구간으로 나눠 긴 프레임에서도 과하게 지나치지 않게 한다. 이동 요청이 끝나면 처음 계산한 제동력을 정지할 때까지 유지해, 추가 미끄러짐을 최대 0.18 이내로 끝낸다. 별도의 Rigidbody나 물리 월드에 판정을 맡기지 않는다. 바닥의 앞뒤 범위는 기준 높이 ±1.2 이내로 제한한다.

- 편성의 처음 물러섬과 제동은 실제 시간을 사용한다. 편성의 느린 다가감은 화면 시계를 따라 Tab 확인 중 0.2배, 기술 설명을 읽는 동안 0.3배로 느려진다. 교전·턴 정리는 전투 시계를 따라 히트 스톱과 슬로모션을 함께 따른다. ESC 정지 중에는 바닥 이동과 표시도 멈춘다.
- 접근 완료는 가로 교전 거리 4를 사용한다. 2026-10-17부터 Y 간격·Y 속도를 공격 시작 조건에서 제외하고, 상대 높이로 끌어당기는 자동 정렬도 제거했다. 처음 접근과 회피·밀림 뒤 재접촉, 다인전 교대와 대전에 동일하게 적용한다. 세로 관성이 남아 있어도 가로 범위에 들어오면 공격을 시작할 수 있다. 가로 이동 중 세로 관성은 시작 때 정한 제동력으로 추가 이동0.18 이내에서 멈춘다.
- 허수아비의 Y 위치는 고정한다. 엘리사도 자신의 높이에서 가로 거리만 좁혀 공격한다.
- 1대3 준비에서는 세 적이 개별 속도 배율로 동시에 X 방향으로 다가온다. 교대 예정자는 현재 기술의 마지막 타격 뒤 자신의 실제 높이에서 미리 접근하고 준비 그림을 유지한다. 도착 전후의 실제 위치와 속도는 다음 교대로 이어지며, 공격 판정은 원래 칸에서만 시작한다. 세부 계약과 조절은 `TrioBattle.md`를 따른다.
- 카메라의 하단 여백은 실제 원·지면 그림자의 가장 낮은 부분을 기준으로 잡아 대기열 UI 위에 남긴다. 복도 배경 하단이 부족할 때는 기존 바닥의 끝 부분을 재사용해 내려간 카메라 영역을 채운다. 세로 이동은 전장의 `Tick`이 한 번만 진행하고, 접촉 거리 재확인에서 중복 진행하지 않는다.
- 대전의 거울 화면은 X만 뒤집는다. 같은 사람의 Y 위치와 앞뒤 순서는 양쪽 화면에서 일치하며, 같은 높이의 순서도 방장 쪽 인물을 기준으로 고정한다.

## 앞뒤 정렬과 바닥 원

각 인물의 몸·하체·그림자·붙어 있는 오라를 하나의 `SortingGroup`으로 묶는다. 실제 발의 Y가 낮은 사람은 앞(0), 높은 사람은 뒤(-1)에 그려 겹치는 순간에도 몸의 일부만 앞뒤가 바뀌지 않는다. 그룹 안의 기존 부위별 순서는 유지한다. 이 두 순서는 바닥 배경(-5)과 숲의 앞쪽 식물(+1) 사이에 있어, 인물이 배경 뒤로 사라지거나 앞쪽 식물을 뚫고 나오지 않는다.

스테이지 5의 1대3에서는 네 몸체를 같은 실제 발 Y 기준으로 -3부터 0까지 정렬한다. 원은 모두 -4, 다인전 잔상도 모든 몸체 뒤에 두며, 개별 사망·교대와 준비의 전체 구도/실행의 교전 구도는 `TrioBattle.md`를 따른다. 1대1에서는 기존 두 순서를 사용한다.

발밑에는 속이 빈 타원형 원을 둔다. 내 캐릭터는 따뜻한 금색, 상대는 차가운 강철색이다. 원은 전장에 두 개를 한 번 만들고 실제 발 위치를 따라 움직인다. 두 인물 모두의 뒤(-4)에 그려 상대 몸을 덮지 않는다. 스프라이트의 투명 여백·공격 돌출·포즈별 외곽선으로 바닥을 추측하지 않는다.

컷신과 시작 장면에서는 전투용 원과 그룹 정렬을 끄고, 장면이 정한 기존 순서를 사용한다. 전투 중 컷신에서 돌아오면 저장한 위치와 앞뒤 표시를 복원한다. 초기화는 두 원을 재사용하고 전투 화면이 열릴 때 다시 표시한다. 대전의 기존 행동 차례 표시는 별도로 유지한다.

## 조절

`DuelPresentationSettings`의 **자동 전투 동선 — 바닥의 앞뒤 이동** 항목을 사용한다. 자산에도 아래 기본값을 기록한다.

| Inspector 항목 | 코드 속성 | 기본값 | 뜻 |
|---|---|---:|---|
| Auto Depth Enabled | `AutoDepthEnabled` | 켜짐 | 실제 위치에 따른 앞뒤 접근·밀림·회피 이동 사용. |
| Combat Depth Travel Speed | `CombatDepthTravelSpeed` | 2.8 | 앞뒤 속도 상한(월드 단위/초). 기존 Movement Speed Multiplier도 곱한다. 범위 0.1~8. |

기존 `combatDepthSpread`·`combatDepthExchangeOffset` 필드와 읽기 속성은 자산 호환을 위해 보존하되 Inspector에서 숨긴다. 저장된 값으로 고정 위치를 선택하지 않는다. 가속·제동과 회피 옆 디딤은 이번 단계에서는 코드 상수이며 새 조절 항목을 추가하지 않는다.

표시는 Presentation의 `LegacyArenaView.Depth.cs`·`DuelGroundCircle.cs`, 동선은 `LegacyArenaView.DepthMotion.cs`·`DuelGroundTravel.cs`, 밀림 방향과 회피 옆 디딤은 `LegacyArenaView.GroundForces.cs`가 맡는다. 실제 발 위치는 `PlayerGroundPosition`·`EnemyGroundPosition`이며, 카메라의 하단 가시성 보정은 현재 더 낮은 발을 기준으로 한다. 월드 공간 잔상은 두 인물 그룹보다 뒤에 유지한다.

기존 입력과 전투 규칙·네트워크 메시지는 추가하거나 변경하지 않는다. 이 문서는 동선과 표시의 계약이며, 실행 검증 결과는 `Validation.md`에 기록한다.
