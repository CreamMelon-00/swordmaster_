# 다이얼로그 편집기

## 열기

Unity 상단 메뉴에서 `Turn Limbo → 다이얼로그 편집기`를 연다.

편집기는 `Assets/Game/Resources/Dialogue/` 아래의 UTF-8 `.txt`만 다룬다. 새 문서는 내용이 없는 파일로 생성하며 예시 스토리를 자동으로 넣지 않는다.

## 기본 작업 흐름

1. `새 문서`에서 파일 이름과 위치를 정한다.
2. 왼쪽 원문 영역에 직접 쓰거나 오른쪽 `빠른 입력`으로 내레이션·좌측 화자·우측 화자 블록을 추가한다.
3. 상단 검사 결과에서 표시 줄 수와 오류 줄 번호를 확인한다.
4. 규칙 검사를 통과하면 화자별 `Sprite`를 지정하고 현재 줄의 좌우 무대 미리보기를 확인한다.
5. 기본으로 켜진 자동 저장을 사용하거나 `저장`을 누른다.

빈 문서와 규칙 오류가 있는 문서도 초안으로 저장할 수 있다. 다만 오류가 남은 파일은 게임에서 열리지 않는다.

## 저장과 충돌 보호

- 자동 저장은 입력이 멈춘 뒤 약 0.8초 후 실행된다. 자동 저장을 꺼도 창을 닫거나 스크립트가 다시 컴파일될 때 남은 변경을 한 번 저장해 작업 유실을 막는다.
- 파일은 BOM 없는 UTF-8과 LF 줄바꿈으로 저장된다.
- `다른 이름`은 현재 원문만 새 파일로 저장한다. 화자 이미지는 프로젝트 공용 설정이므로 그대로 재사용된다.
- 외부 텍스트 편집기에서 같은 파일이 바뀌면 자동 저장을 멈추고 `외부 변경 다시 읽기` 또는 `현재 내용으로 덮어쓰기`를 선택하게 한다.
- 저장에 실패하면 반복 저장을 멈추고 창 안에 원인과 `저장 다시 시도` 버튼을 유지한다.
- 외부 변경 충돌이나 저장 실패를 해결하지 않은 채 창이 닫히면 `Library/TurnLimbo/DialogueRecovery/`에 원본 경로와 작성 내용을 함께 담은 복구본을 남긴다. Unity를 다시 실행한 뒤에도 최신 복구본을 찾아 복구 또는 폐기를 선택할 수 있다.
- 복구본을 연 것만으로는 파일을 지우지 않는다. 원본 또는 `다른 이름` 저장이 성공하거나 사용자가 명시적으로 버릴 때 정리한다.
- 저장은 같은 폴더의 임시 파일을 완성한 뒤 원본과 교체해 중간 실패로 원본이 잘릴 가능성을 줄인다.
- 원문을 기준 데이터로 유지하므로 직접 작성한 주석과 공백을 구조화 데이터로 재생성하지 않는다.

## 빠른 입력

빠른 입력은 원문 끝에 현재 문법에 맞는 블록을 추가한다.

- 내레이션 또는 좌·우 위치 선택
- 화자 이름과 선택적인 역할·호칭
- 한 번에 표시할 문장
- 선택적인 화자 이미지
- 문장이 `@` 또는 `#`으로 시작하면 자동 이스케이프
- 빈 이름, 줄바꿈, `|` 오용, 240자 초과를 추가 전에 안내

빠른 입력은 기존 원문을 다시 정렬하거나 정규화하지 않는다.

## 화자 이미지 무대 명령

등장·퇴장·이동은 원문에 다음 문법으로 적는다. `<...>`는 작성할 값이고 `[...]`는 생략할 수 있는 부분이며, 괄호 자체는 입력하지 않는다.
오른쪽 `무대 연출` 영역에서 명령과 위치를 선택해 같은 문법을 원문 끝에 안전하게 추가할 수도 있다. 등장 명령에서는 선택적으로 화자 이름·역할·이미지를 함께 지정한다.

```text
@show <left 또는 right> [<화자 이름> | <역할·호칭>]
@hide <left 또는 right>
@move <left 또는 right> <left 또는 right>
```

- 기존 `@left`와 `@right` 블록은 화자를 선택하는 동시에 해당 위치의 이미지를 자동으로 표시한다.
- 이름 없는 `@show left` 또는 `@show right`는 그 위치에 마지막으로 등록한 화자를 다시 표시한다. 이름을 함께 적으면 화자를 등록하거나 교체한다.
- `@hide`는 지정한 위치의 이미지를 숨긴다. 이미 비어 있는 위치는 규칙 오류로 안내한다.
- `@move left right`와 `@move right left`는 보이는 출발 위치의 화자를 빈 목적지 위치로 옮긴다. 출발 위치가 비어 있거나 목적지 위치가 차 있으면 규칙 오류로 안내한다.
- 이미지는 숨김·교체·이동 명령 전까지 유지된다. 현재 화자만 밝게, 말하지 않는 화자는 어둡게 보이며 나레이션에서는 양쪽 모두 어둡게 보인다.
- 무대 명령은 실제 대사나 나레이션이 아니므로 표시 줄 수와 진행 번호에 포함되지 않는다. 명령 뒤의 다음 실제 문장에서 결과를 확인할 수 있다.

## 화자 이미지

규칙 검사를 통과한 문서에서 발견한 화자 이름마다 `Sprite`를 지정할 수 있다. 처음 이미지를 지정할 때 `Assets/Game/Resources/DialoguePortraitCatalog.asset`이 자동 생성된다.

- 연결 기준은 대소문자를 포함한 정확한 화자 이름이다.
- 같은 이름의 화자는 모든 다이얼로그 파일에서 같은 기본 이미지를 사용한다.
- 역할·호칭을 바꿔도 이름이 같으면 연결이 유지된다.
- 이미지를 비우면 해당 화자의 연결을 제거한다.
- 이미지가 지정되지 않은 화자는 해당 위치의 초상화만 표시하지 않으며 대사와 이름표는 정상적으로 진행된다.
- 내레이션은 현재 무대에 남아 있는 좌우 이미지를 숨기지 않고 둘 다 어둡게 표시한다.
- 현재 버전은 화자 한 명당 기본 이미지 한 장만 지원한다. 표정 변화는 스토리 요구가 확정된 뒤 별도 키로 확장한다.

## 검사 결과

편집기는 게임과 같은 `DialogueScriptParser`를 사용한다. 따라서 도구에서 통과한 원문과 런타임 규칙이 따로 어긋나지 않는다.

오류에는 가능한 경우 원본 줄 번호가 함께 표시되며, 원문 왼쪽의 줄 번호 영역에서 위치를 바로 찾을 수 있다. 이동할 출발 위치가 보이지 않거나 목적지 위치가 비어 있지 않은 경우처럼 무대 상태에 맞지 않는 명령도 해당 줄에서 오류로 표시한다. 빈 초안은 작성 중인 정상 상태로 안내하지만, 주석이나 지시어만 있고 실제 표시 문장이 없는 파일은 오류로 구분한다.
