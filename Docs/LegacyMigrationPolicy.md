# Legacy Migration Policy

## 원칙

구 프로젝트는 복구 대상이 아니라 참고 자료와 리소스 원본 보관소다. 신규 프로젝트가 구 프로젝트의 기술 부채를 다시 흡수하지 않도록 아래 경계를 지킨다.

## 허용하는 작업

- 코드와 CSV를 읽어 기존 게임 규칙과 콘텐츠 의도를 확인
- 이미지, 애니메이션 클립, UI, 파티클, 오디오, 폰트의 의존성과 라이선스 조사
- 사용자가 요청한 원본 전투 리소스를 작은 단위로 복사한 뒤 신규 프로젝트에서 재임포트
- 스프라이트 분할처럼 가치 있는 임포트 설정이 있을 때만 해당 `.meta`를 선별 검토
- 표현 전용 파티클 프리팹·머티리얼·텍스처를 필요한 의존성과 함께 선별 복사하고 Unity 6에서 참조 검증
- 원본 클립의 스프라이트 곡선·타격 시간을 사용하되 전투 판정은 새 순수 C# Runtime이 소유하도록 연결

## 하지 않는 작업

- 구 프로젝트의 컴파일 오류 수정
- 구 패키지 업데이트 또는 ProjectSettings 정리
- 구 씬·게임플레이 프리팹·레거시 스크립트 의존성을 통째로 신규 프로젝트에 복사
- `Assets/Plugins`, `Packages`, `ProjectSettings` 일괄 이식
- 런타임 Google Sheets 로딩 구조 이식
- 권리 확인 없이 외부에 리소스 또는 빌드를 공개 배포

## 예외 조건

신규 구현에 필요한 규칙이나 리소스 연결 관계를 정적 파일만으로 확인할 수 없을 때만 예외를 검토한다. 예외가 필요해도 구 프로젝트를 일반적인 실행 상태로 복구하는 작업은 자동으로 시작하지 않으며, 별도 결정으로 남긴다.

## 현재 이식 경계

현재 이식은 플레이어와 신입생 한 명, 기본 9개 기술의 편성→큐 확정→타격별 해결→턴 복귀→승패·재대결을 대상으로 한다. 표현은 원본 Sprite·12fps 클립·UI·충돌 파티클을 사용해 월드 전장과 uGUI HUD로 재구성한다. 접근·밀림·카메라·타격 시점도 원본에서 확인한 규칙을 따른다.

캠페인 스테이지 전환, 시나리오, 저장 덱, 상점, 성장, 체인과 전체 로그라이크 진행은 이번 범위에 포함하지 않는다. 기본 9개는 원본 신규 소유/로그라이크 시작 구성으로, 기존 캠페인 저장 데이터를 가져오지 않는다. 스텝이나 새로운 피지컬 규칙은 원본 전투를 확인한 뒤 별도 설계한다. 이 범위를 위해 구 프로젝트 전체를 실행 가능하게 복구하지 않는다.

## 리소스 이식 게이트

로컬 전투 확인을 위한 이식은 사용자의 원본 리소스 재사용 요청에 따라 진행한다. 기초 아트 목록과 경로는 `LegacyAssetManifest.md`, 추가 전장·HUD 리소스와 대응은 `LegacyPresentationAssets.md`·`LegacyHudParity.md`에 기록한다. 출시 전에는 다음 네 단계를 모두 확인한다.

1. 소유권과 배포 라이선스 확인
2. 실제 신규 수직 슬라이스에 필요한지 확인
3. URP 2D와 Unity 6에서 기술 호환성 확인
4. 새 명명 규칙과 폴더 구조로 임포트하고 참조 검증
