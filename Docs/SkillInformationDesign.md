# 스킬 정보 카드

전투의 기술 확인에는 조건에 맞는 적 큐 카드와 다음 예약 칸의 준비 상태를 밝은 청록 테두리와 큰 표식으로 표시한다. 실제 발동은 금색으로 구분한다. 양측 상태창의 현재/새로 받은 버프 수치와 카드의 전투 버프 입자는 Runtime 스냅샷을 따르며, 기술 그림에서 추측하지 않는다. 상세 계약은 `SkillConditionFeedback.md`를 따른다.

2026-09-27. 설명 내부를 숫자3칸으로 분할하지 않고, 종이 카드 가장자리에 ACT 인장·위력 금속판·타입 리본을 별도로 붙인다. 본문에는 핵심 키워드와 짧은 조건 문구만 남긴다. 19세기 검술 클럽의 종이/잉크/황동 팔레트, 실제 기술 아이콘과 기존 조작을 유지한다. 새 이미지나 패키지는 추가하지 않는다.

## 읽는 순서

1. 큰 기술 배지와 이름, Q 정공·W 강공·E 기교 검술 표식. 기술 강화를 잠시 뺐으므로 편성 상세 제목에는 강화 단계를 붙이지 않는다.
2. 제목 왼쪽의 원형 ACT 인장, 제목 오른쪽의 타입 리본, 본문 왼쪽 아래의 위력/방어 금속판. 리본에는 참격/타격/관통/방어를 글자로 명시하고 타격 수 또는 같은 칸 대응을 함께 표시한다. 각인 기호에 짧은 이름을 함께 붙여 기호만 외우게 하지 않는다.
3. 핵심 키워드 배지 최대2개: ACT+1, 조건부 ACT+2, 후속+10%, 고화력, 분할 연타, 피해-30%, 위력 편차 등. 의미별 배경색과 잉크색을 사용하되 기호·라벨을 항상 함께 표시한다.
4. 조건과 적용 시점: 같은 칸의 상대 타격, 다음 턴, 이번 턴 뒤3칸/최대10칸 등을 별도 짧은 줄로 표시한다.

커리큘럼과 편성의 전체 페이지 안 선택 상세, 전투의 키 홀드/적 확인 팝업은 `SkillInfoView`를 공유한다. 키 홀드 팝업은 큰 배지와 기술명/열, 공용 정보 카드, 놓으면 닫기 안내를 사용한다. 2026-10-07부터 키 홀드 팝업은 같은 카드를 1.25배(종이·글자·외부 표식, `SkillInfoView`의 `scale`)로 어두운 그림자 위에 그린다(아래 '전투의 길게 눌러 설명'). 기술을 바꿔 보아도 정보 창과 상세판의 바깥 크기는 변하지 않는다. 본문·배지 등 정해진 영역에 문구가 넘치면 해당 텍스트의 크기를 줄여 영역 안에 맞춘다. 좌우 여유를 포함해 외부 표식까지 화면 안에 둔다. 키 해제/Tab 해제/로그·턴 전환의 닫기 동작은 그대로다. 편성·커리큘럼은 페이지 오른쪽의 고정 종이 상세판을 사용한다. 보유 목록은 현재 편성에 없는 기술만 표시하고 열린 Q/W/E열을 동시에 보여 준다. 기술을 선택하면 같은 열의 슬롯을 강조하며, 강조된 슬롯 클릭 또는 드래그로 배치한다. 각열3개 저장 규칙과 하단 저장 버튼은 유지한다. 커리큘럼 상세는 얻는 기술의 공용 카드 아래에 선행·택1·상태 안내와 단일 `이 과정 진행` 버튼을 붙인다. 슬롯 목록에는 새 타입 문구를 추가하지 않는다.

## 전투의 길게 눌러 설명 (2026-10-07, 작가 요청)

- **열기.** Q/W/E나 그 열 톱니의 창을 0.35초 누르고 있으면 그 열 지금 기술의 설명이 열린다(전에는 1초). 0.2초 안에 떼면 예약이다(전에는 0.3초). 열린 뒤 떼면 예약하지 않고 닫는다. 두 시간은 튜닝이다(`PresentationTuning.md`의 '길게 눌러 설명').
- **읽기 쉽게.** 내용과 읽는 순서(배지와 기술명, Q/W/E 검술 표식과 키, ACT 인장·위력판·타입 리본, 키워드, 효과·조건 문구, 닫기 안내)와 오브젝트 이름은 그대로 두고, 카드 전체를 적 확인 팝업의 1.25배로 키웠다. 종이(`Paper`)와 잉크(`Ink`)는 그대로이며, 카드 밑에 어두운 그림자를 깔아 밝은 전장 위에서도 경계가 또렷하다. 정해진 영역에 넘치는 문구를 줄이는 규칙도 같은 비율의 최소 크기로 적용한다.
- **자리.** 조작대 위쪽 가장자리 바로 위에, 누른 열의 창 가운데에 맞춘다. 화면 끝에서는 외부 표식까지 화면 안으로 당긴다. 톱니(조작대 안에 잘림)와 머리 위 상태·큐가 가리지 않는다. 톱니가 도는 동안에도 창 자리를 따르므로 흔들리지 않는다. 코치 카드가 조작대 위에 떠 있는 동안(안내 단계마다, 자유 단계에도)은 그 카드 바로 위에 연다. 카드는 전투 HUD 위에 그려지므로, 조작대 위에 열면 효과·조건 문구와 위력판이 카드 밑에 가려진다.
- **시간.** 설명을 읽는 동안 편성 시간이 0.3배로 흐르고, 전투에서는 불릿타임의 다가감도 같이 느려진다(Tab 확인의 0.2배와 같은 방식). 편성 밖에서는 느려지지 않는다.
- 적 확인(Tab) 팝업은 크기·자리(왼쪽 위 고정)를 바꾸지 않았다.
- **맞물림 줄**(2026-10-08, `Meshing.md`). 맞물릴 수 있는 전투(열린 열이 둘 이상이고 퍼센트가 0보다 큼)에서는 길게 눌러 연 카드의 닫기 안내 위에 작은 톱니와 한 줄을 더한다. 그 기술을 지금 예약하면 맞물리면 `맞물림 · 지금 예약하면 위력 +40%`(굵게, 사슬 길이 × 퍼센트), 아니면 `맞물림 · 다른 열 기술 바로 뒤에 예약하면 위력 상승`이다. 기술 자체의 효과가 아니라 지금 큐에서의 자리를 말하므로 본문·키워드가 아니라 안내 쪽에 둔다. 큐·ACT·넘기기에 따라 바뀌지만, 줄은 한 전투 내내 있거나 없어 카드의 바깥 크기는 그대로다(줄이 있는 전투에서 22×1.25만큼 크다). 열이 하나뿐인 전투, 편성·커리큘럼 상세, 적 확인 팝업에는 없다(`LegacyCombatHud.MeshNoteText`).

## 고정 크기 배치

정보 카드의 본문 영역과 외부 창은 정해진 크기를 유지한다. 내용 길이에 따라 높이를 늘리던 배치는 종료한다. 위력 표식은 본문 옆에, ACT/타입 표식은 제목 높이에 둔다. 본문 왼쪽 여유는 위력 표식과의 겹침을 막는다. 키워드가 2개면 나란히, 1개면 가용 폭을 쓴다. 글자가 긴 기술은 영역별 텍스트 자동 축소로 표시하고, 짧은 기술의 글자 크기는 기본값을 유지한다.

전투 팝업에는 닫기 안내를, 편성 상세에는 필요한 경우 해제 버튼을 고정 영역에 둔다. 빈 편성은 오래된 타입·수치·키워드를 숨기고 같은 크기의 안내를 보여 준다. 커리큘럼은 과정 이름과 `<계열> 과정 · 전투 N회`, 카드 아래의 구분선·선행·택1·상태 안내·진행 버튼을 정해진 판 안에 배치한다. 기술을 주지 않는 능력치 과정은 공용 기술 카드 대신 능력치 보상을 보여 준다. 카드 선택이나 로비 페이지 전환 때만 내용을 갱신한다.

## 검술 분류

Q=정공 검술(황동 종이), W=강공 검술(청록 종이), E=기교 검술(적동 종이)로 이름을 통일한다. 이는 기존 `LegacySkill.LaneIndex`의 표시 이름이며 참격/타격/관통/방어 타입이나 새로운 보너스 효과가 아니다. W의 알티바호는 강공 검술·참격이고 각 검술의 방어도 같은 분류를 유지한다. 키, 큐, 편성 제한, 실제 판정은 바꾸지 않는다.

전투 Q/W/E 버튼에 짧은 검술 이름을 붙인다. 전투 설명 제목과 편성 열 제목·선택 상세, 커리큘럼 상세는 같은 분류 이름을 사용한다. 선택 상세에는 염색 종이/황동 테두리의 분류 표식과 작은 키 각인을 붙인다. 적 정보는 분류 이름만 표시하고 플레이어 입력 키는 숨긴다. 플레이어가 세 검술을 모두 열기 전까지 적 기술은 분류 이름 대신 중립 표식 `상대 기술`을 달고, 아래 안내도 `상대 기술 · Tab / 적 확인` 대신 `Tab / 적 확인`만 쓴다(`LegacyCombatHud.EnemySkillCaption`, `StoryUnlocks.md`). 빈 선택은 이전 분류/키를 지운다. 편성 슬롯에는 설명 텍스트를 더하지 않고 기존 세 텍스트 계약을 유지한다. 커리큘럼 트리 카드도 아이콘·열 키·(택1 과정이면) `택1` 표시·이름·상태만 둔다. 제목/키/장식은 입력을 가로채지 않으며 갱신 때 새 노드를 생성하지 않는다. `SkillLaneStyle`이 이름·키·색 매핑을, `SkillLaneBadge`가 재사용 표시를 소유한다.

‘공격·방어 모두 적용’은 모든 기술의 공통 효과가 아니라 3/9번 후속 위력 강화의 적용 대상이다. 현재 규칙에서 위력 배율은 뒤쪽 공격과 방어의 수치 모두에 적용된다. 이번 분류 변경은 해당 설명이나 효과를 변경하지 않는다.

## 타입 표식

공격 타입은 아이콘·이름·검술 분류가 아니라 현재 `LegacySkill.Property`에서 읽는다. Slash=참격(적동), Hit=타격(황동), Penetrate=관통(강철청), Defence=방어(올리브)이며 리본 배경과 짙은 잉크를 함께 바꾼다. 공격은 ‘공격 타입’, 방어는 ‘기술 타입’이라고 표시하고 방어 수치를 공격 위력과 혼동하지 않게 한다. 적 정보도 실제 Skill 복사본(스테이지 보정 포함)을 따르며 타입 이름 자체가 추가 피해 효과를 의미하지 않는다. 전투 상단의 중복 타입 문구는 검술 분류 표식으로 정리한다.

## 키워드 색 언어

채도가 낮은 염색 종이와 짙은 잉크로 19세기 검술 클럽 테마를 유지한다. 각 키워드 칸의 배경은 불투명(alpha 1)이며 글자와 기호는 같은 잉크색을 쓴다. 글자/배경 대비는 최소4.5:1을 목표로 한 아래 팔레트다. 황동 테두리는 기존 공용 테마를 유지한다.

| 의미 | 잉크·기호 | 배지 배경 | 대표 키워드 |
|---|---|---|---|
| ACT 회복 · 차분한 녹빛 | `#24594B` | `#C5D4B6` | ACT+1, 조건부 ACT+2, 다음 턴 |
| 후속 강화 · 자주 | `#59416B` | `#D7C5D6` | 후속+10%, 뒤3칸, 위력 지원 |
| 피해 감소 · 강철청 | `#33516B` | `#C6D3D9` | 피해-30%, 후속 보호 |
| 고화력 · 적동 | `#743D2D` | `#DCC3AD` | 고화력 |
| 연타 · 황동 | `#664B20` | `#DFCEA3` | 분할 연타 |
| 위력 편차 · 황토 | `#6A4C19` | `#E0D0A6` | 위력 편차 |
| 방어 · 올리브 | `#45522F` | `#CAD0AE` | 수치 방어, 타격 대응 |
| 기본 공격 · 중립 | `#493F31` | `#D7C9AC` | 단타 |

색은 키워드의 의미에 대응하며 스킬 종류 전체를 덮는 색이 아니다. 예를 들어 조건부 ACT 회복은 녹빛 회복 배지와 올리브 대응 조건 배지를, 고화력 연타는 적동 고화력 배지와 황동 연타 배지를 함께 보여준다. 색을 구분하기 어려워도 문구와 각인 기호로 역할·조건을 읽을 수 있다.

## 의미 계약

- 추가 일반 기술은 준비(10)의 이번 턴 다음 1칸 공격·방어 위력 +30%, 플레슈(12)의 다음 턴 ACT +3와 이번 턴 다음 1칸 받는 피해 +50%, 르프리즈(19)의 시작 시 최대 저항 10% 회복, 쿠페(42)의 시작 시 같은 칸 상대 방어 조건 저항 -20/다음 ACT +3를 표시한다. ACT는 플레이어 전용이고 회복/직접 감소는 저항 상·하한을 적용한다. 별칭 그림에서 효과를 추론하지 않는다. 구작 코드와 설명의 차이는 `ImportedNonChainSkills.md`를 따른다.
- 숫자는 선택한 실제 `LegacySkill`을 읽는다. 적 기술의 위력은 스테이지 보정 복사본을 따른다. 위력은 총 피해나 확정 피해가 아니다.
- 연타 기술은 실제 타수만 수치표에 표시한다. 타격당 위력 계산 방식은 개별 스킬 설명에 반복하지 않는다.
- 7번은 같은 슬롯의 상대가 타격 기술인 조건으로 다음 턴 ACT+2. 방어 성공이나 피해 발생 조건을 임의로 추가하지 않는다. 적 팝업에는 ACT 회복이 플레이어 전용이라고 명시한다.
- 8/9의 후속 피해 감소/위력 지원은 이번 턴 뒤 최대10칸이며 턴을 넘어 지속되지 않는다. 추가 기술14/17/32에는 구현되지 않은 회복·회피·지원 효과를 붙이지 않는다.
- 공격끼리의 대결은 저항, 방어·빈칸과의 대결은 체력으로 이어지는 공통 시스템 규칙이므로 개별 스킬 카드에 피해 경로 두 줄을 반복하지 않는다. 기존 피해 판정은 바꾸지 않는다. 베기/찌르기/타격은 같은 규칙을 따르며 관통=방어 무시, 타격=저항 특화, 고화력=치명타라고 표시하지 않는다.

## 구성과 수명

`SkillInfoView`는 생성 시 외부 표식3개/키워드 배지/본문과 배지 Image 참조를 만들고 선택한 Skill 참조가 바뀔 때만 문구·기호·색을 갱신한다. 빈 선택은 타입과 숫자를 지우고 표식/키워드를 숨긴다. 구형 ACT/Power/Hits Tile을 생성하지 않는다. `Damage Routing` UI는 생성하지 않으며 기존 소비자 호환용 `DamageText`만 빈 문자열의 비활성 Text로 유지한다. `SkillInfoAttachment`는 원형/금속판/리본의 종이와 황동 테두리를 그리는 캐시된 점 기반 비차단 uGUI 메시다. `SkillInfoGlyph`는 CanvasRenderer를 갖는 비차단 uGUI 메시로 ACT/검/대응/반복/순환/후속/감소/편차 기호를 그린다. 글자·아이콘·장식은 raycast를 받지 않고 뷰 소유자가 기존 루트와 함께 폐기한다. Runtime/기존 자산/씬/프리팹/설정 변경은 없다. 실행 검증과 지원 해상도 한계는 `Validation.md` 최신 항목을 따른다.
