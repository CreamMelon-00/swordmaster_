# 기술 시트

2026-10-02 도입. 당시 기술 19종의 이름·수치·효과·문구를 C# 코드에서 꺼내 CSV 시트 하나로 옮겼습니다. 기획자는 이 시트를 Excel이나 구글 시트에서 고치면 되고, 코드를 고칠 필요가 없습니다. 도입 당시에는 기술 네 개의 이름만 바뀌었습니다(아래 [이전 이름](#이전-이름)). 2026-10-03에는 스테이지 첫 승리 보상 탐색(43)·몰아치기(44)를 더해 현재 21종입니다(`CampaignLoop.md`).

시트가 담지 않는 것도 있습니다. 서막 임무의 연습 기술(연습 베기·연습 내려치기·연습 막기)과 공용 행동 숨고르기는 코드에 있습니다. 어느 커리큘럼 과정이나 스테이지 첫 승리가 어느 기술을 주는지(`Curriculum.md`, `CampaignLoop.md`), 스테이지 적이 어떤 순서로 기술을 쓰는지(`EnemyRhythms.md`)도 코드에 있습니다.

## 파일

- 위치: `Assets/Game/Resources/Skills/skills.csv`
- 형식: 쉼표로 나눈 CSV, UTF-8(BOM 있음). 첫 행은 열 이름이고, 그 아래 한 행이 기술 하나입니다.
- 게임은 구글 시트가 아니라 **이 파일**을 읽습니다. 구글 시트에서 고친 내용은 받아오기로 이 파일에 옮겨야 게임에 들어갑니다.
- 고친 파일은 git에 커밋해야 팀이 같은 기술 표를 씁니다.
- 파일 이름과 위치를 바꾸지 마세요. 게임은 이 경로만 읽고, 옮기거나 지우면 Console에 오류가 뜹니다.

Unity 상단 메뉴 `Turn Limbo → 기술 시트`를 열면 이 파일을 다루는 버튼이 있습니다.

| 버튼 | 하는 일 |
|---|---|
| `구글 시트에서 받아오기` | 구글 시트를 CSV로 받아 검사하고, 바뀐 내용을 보여 준 뒤 확인하면 파일을 덮어씁니다. |
| `시트 열기` | 주소 칸의 구글 시트를 브라우저로 엽니다. |
| `CSV 검사` | 지금 파일을 게임과 같은 규칙으로 검사해 결과를 보여 줍니다. |
| `CSV 파일 열기` | 파일을 기본 프로그램(보통 Excel)으로 엽니다. |
| `폴더에서 보기` | 파일이 있는 폴더를 탐색기로 엽니다. |

결과는 창 아래에 나옵니다. 문제·변경 목록이 길면 스크롤하고, `결과 복사`로 목록 전체를 클립보드에 복사할 수 있습니다.

## Excel로 고치기

1. `CSV 파일 열기`나 파일 더블클릭으로 Excel에서 엽니다. BOM이 있어 한글이 바로 보입니다.
2. 칸을 고칩니다. 칸 안에서 줄을 바꾸려면 Alt+Enter를 누릅니다.
3. **파일 → 다른 이름으로 저장 → 파일 형식 `CSV UTF-8(쉼표로 분리)`**로 저장합니다. 그냥 `CSV(쉼표로 분리)`로 저장하면 파일이 UTF-8이 아니라 게임이 한글 열 이름을 모두 읽지 못하고, `1행: 파일이 UTF-8이 아닙니다(한글이 깨져 읽힙니다). Excel에서 파일 → 다른 이름으로 저장 → CSV UTF-8(쉼표로 분리)로 다시 저장하세요.` 오류가 납니다. Excel로 다시 열면 한글이 멀쩡히 보이니, 열 이름의 철자가 아니라 저장 형식을 고치면 됩니다. 서식이 사라진다는 경고가 뜨면 CSV 형식을 유지합니다.
4. Unity 창으로 돌아오면 Unity가 파일을 다시 가져오고(자동 새로 고침이 꺼져 있으면 Ctrl+R), 문제가 있으면 Console에 바로 빨간 오류가 뜹니다. `CSV 검사`로도 확인할 수 있습니다. Excel을 닫지 않아도 됩니다.

- 칸 맨 앞에 `=`를 적으면 Excel이 수식으로 바꿉니다.
- Excel이 파일을 열고 있어도 Console 검사, `CSV 검사`, 게임은 파일을 읽습니다. 다만 받아오기는 Excel이 연 파일을 덮어쓰지 못합니다. Excel을 닫고 다시 받아오세요.

## 구글 시트로 고치기

### 처음 한 번 설정

1. 구글 드라이브에서 새 스프레드시트를 만듭니다.
2. **파일 → 가져오기 → 업로드**에서 `skills.csv`를 고릅니다. 가져오기 위치는 `현재 시트 바꾸기`, 구분자는 `쉼표`로 둡니다. `텍스트를 숫자, 날짜, 수식으로 변환`은 꺼 두는 편이 안전합니다(칸을 적힌 그대로 둡니다).
3. 공유를 엽니다. 오른쪽 위 **공유 → 일반 액세스**를 `링크가 있는 모든 사용자`, 역할 `뷰어`로 바꿉니다. 함께 고칠 사람은 따로 편집자로 초대합니다.
   - 회사 계정이라 바깥 공유가 막혀 있으면 **파일 → 공유 → 웹에 게시**로 게시해도 됩니다.
   - 둘 다 하지 않으면 구글이 CSV 대신 로그인 화면을 보내고, 받아오기가 실패합니다.
4. 받을 탭을 연 상태에서 브라우저 주소창의 주소(`https://docs.google.com/spreadsheets/d/…/edit#gid=…`)를 복사해 Unity `Turn Limbo → 기술 시트` 창의 **주소** 칸에 붙여 넣습니다. 웹에 게시에서 받은 주소(`…/spreadsheets/d/e/…/pubhtml`)도 됩니다.
   - 주소의 `gid`가 탭 번호입니다. 주소에 `gid`가 없으면 맨 처음 만든 탭(`gid=0`)을 받습니다.
   - 주소는 `ProjectSettings/TurnLimboSkillSheet.asset`에 저장됩니다. 이 파일을 커밋하면 팀 모두 같은 주소를 씁니다.

### 받아오기

1. `구글 시트에서 받아오기`를 누릅니다. 진행 막대가 뜨고, 최대 20초 기다립니다. 막대의 취소로 멈출 수 있습니다.
2. 받은 시트를 게임과 같은 규칙으로 검사합니다. 문제가 있으면 `받은 시트에 문제가 N개 있어 CSV를 바꾸지 않았습니다.`와 함께 문제 목록을 보여 주고, 파일은 그대로 둡니다. 구글 시트에서 고친 뒤 다시 받아옵니다.
   - 시트 규칙은 맞아도 게임 코드가 쓰는 기술이 없거나 커리큘럼이 주는 기술이 `시작`이면(아래 [게임 코드와 맞추기](#게임-코드와-맞추기)) `받은 시트가 게임 코드와 맞지 않는 곳이 N개 있어 CSV를 바꾸지 않았습니다.`로 막습니다. 의도한 변경이면 프로그래머가 코드를 먼저 고친 뒤 다시 받아옵니다.
3. 문제가 없으면 지금 파일과 비교합니다.
   - 바뀐 것이 없으면 `바뀐 내용이 없습니다 (기술 21개). CSV를 그대로 둡니다.`처럼 현재 행 수를 알려 주고 끝납니다.
   - 바뀐 것이 있으면 확인 창이 뜹니다.
4. 확인 창에서 `덮어쓰기`를 누르면 파일을 덮어쓰고 Unity가 다시 가져옵니다. `취소`를 누르면 파일은 그대로이고, 바뀐 목록은 창에 남습니다.
5. 덮어쓴 `skills.csv`(처음이면 `ProjectSettings/TurnLimboSkillSheet.asset`도)를 커밋합니다.

확인 창에는 다음이 나옵니다.

- 요약: `추가 1 · 삭제 0 · 변경 2 (기술 20개)`. 행 순서가 바뀌었으면 `· 순서 변경`이 붙습니다.
- 줄마다 하나씩(12줄까지, 나머지는 창의 목록에서 봅니다):
  - `추가: 50 새 베기`
  - `삭제: 42 쿠페`
  - `변경: 16 알티바호 — 이름, ACT` — 바뀐 칸을 열 이름으로 보여 줍니다. `10`과 `10%`처럼 같은 값을 다르게 적은 것은 변경으로 치지 않습니다.
  - `순서: 행 순서가 바뀌었습니다. 시작 기술은 열마다 위에서부터 기본 편성 순서가 됩니다.`
  - `그림: 50 새 베기의 그림 50번이 없어 기술 아이콘이 비어 보입니다. …` — 경고일 뿐 덮어쓰기를 막지 않습니다(아래 [그림](#그림)).
  - `ID 50 새 베기: '구분'이(가) '획득'이지만 이 기술을 주는 커리큘럼 과정이 없어 게임에서 얻을 수 없습니다. …` — 경고일 뿐입니다. 새 기술이면 프로그래머가 과정을 넣을 때까지 이 경고가 납니다.
- 플레이 중이면 `지금은 플레이 중이라 다음 플레이부터 반영됩니다.`

기술 내용은 같은데 메모 열, 주석 행이나 칸 표기만 다르면 `기술 내용은 그대로이고 메모 열, 주석 행이나 칸 표기만 다릅니다`라고 알리고, 파일을 시트와 맞출지 확인 창으로 묻습니다. 지금 파일에 문제가 있어 비교할 수 없으면 그렇다는 줄이 맨 위에 붙고, 받은 기술을 모두 `추가`로 셉니다.

받아오기는 파일 전체를 구글 시트 내용으로 바꿉니다. 구글 시트를 쓰기로 했다면 CSV를 Excel로 따로 고치지 마세요. 그 변경은 다음 받아오기에서 사라집니다(확인 창에 `변경`으로 보이니, 그때 취소하고 구글 시트에 옮겨 적으면 됩니다).

### 받아오기가 실패할 때

| 메시지 | 할 일 |
|---|---|
| `구글 시트 주소가 아닙니다: …` / `구글 시트 주소를 붙여 넣으세요.` | 주소 칸에 위 4번의 주소를 붙여 넣습니다. |
| `구글 시트가 CSV 대신 웹 페이지(로그인 화면 등)를 보냈습니다. …` | 공유가 안 되어 있습니다. 위 3번대로 공유하거나 웹에 게시합니다. |
| `구글 시트가 오류 404(…)로 답했습니다. …` / `… 오류 403(…)으로 답했습니다. …` | 주소나 탭이 틀렸거나 공유가 안 되어 있습니다. |
| `20초 안에 시트를 받지 못했습니다. …` / `시트를 받지 못했습니다: …` | 인터넷 연결을 확인하고 다시 받아옵니다. |
| `받은 시트가 게임 코드와 맞지 않는 곳이 N개 있어 CSV를 바꾸지 않았습니다. …` | 목록의 기술 ID를 되돌리거나, 프로그래머에게 코드를 먼저 바꿔 달라고 합니다([게임 코드와 맞추기](#게임-코드와-맞추기)). |
| `CSV를 쓰지 못했습니다: …` | Excel 등에서 파일을 열어 두었으면 닫고 다시 받아옵니다. |

## 언제 반영되나

- **Play**: Play를 누를 때마다 파일을 새로 읽습니다. 플레이 도중에 바꾼 내용(받아오기 포함)은 진행 중인 게임에 들어가지 않고, 다음 Play부터 반영됩니다.
- **편집 모드**: Unity가 파일을 다시 가져올 때(Excel에서 저장하고 Unity로 돌아올 때, 받아오기 직후) 기술 표를 새로 읽습니다. EditMode 테스트도 새 파일을 봅니다. 이때 파일에 문제가 있으면 Console에 오류가 바로 뜹니다. 게임 코드와 맞지 않는 곳은 빨간 오류(`… 게임 코드와 맞지 않는 곳 N개`), 과정이 없는 `획득` 기술은 노란 경고(`… 경고 N개`)로 뜹니다.
- **문제가 있는 파일로 Play하면** 시작할 때 Console 맨 위에 `기술 시트 'Assets/Game/Resources/Skills/skills.csv': 문제 N개`와 문제 목록이 뜹니다. 게임은 기술을 처음 쓰는 곳에서 같은 오류로 멈춥니다. 파일을 고치고 다시 Play하세요. 시트 규칙은 맞지만 게임 코드와 맞지 않으면 `기술 시트 '…': 게임 코드와 맞지 않는 곳 N개`가, 경고가 있으면 `기술 시트 '…': 경고 N개`가 뜹니다.

## 행과 열

- **첫 행**은 열 이름입니다. 아래 표의 37개 열이 모두 있어야 하고, 이름은 띄어쓰기까지 똑같이 적습니다. 열 순서는 자유입니다. 같은 이름의 열을 두 번 둘 수 없습니다.
- 표에 없는 이름의 열은 **메모 열**입니다. 게임이 읽지 않으니 자유롭게 써도 됩니다.
- 한 행이 기술 하나입니다. 완전히 빈 행은 건너뜁니다. **`ID` 칸이 `#`로 시작하는 행은 주석**이라 건너뜁니다(예: `# 아래는 시험 중인 기술`). 메모 열에만 글자를 적은 행은 빈 행이 아니라 기술로 읽혀 필수 칸 오류가 나므로, 메모 행은 `ID` 칸을 `#`로 시작하세요.
- 칸 앞뒤의 공백은 무시합니다. 칸 안의 줄바꿈은 그대로 화면에 나옵니다.
- 행 번호는 시트의 행 번호와 같습니다. 첫 행이 1행이고, 여러 줄인 칸이 있어도 한 행입니다.
- **행 순서**: `시작` 기술은 열마다 위에서 아래 순서가 새 게임의 기본 편성 순서입니다(지금 Q 베기·연속 베기·막기, W 깊은 찌르기·정교한 찌르기·흘리기, E 기세 꺾기·허점 노리기·쳐내기). 그 밖의 순서는 화면에 영향이 없습니다. 커리큘럼 트리의 배치는 코드(`CampaignCurriculum.cs`)가 정합니다.

## 열 목록

"비우면"이 없는 칸은 꼭 적어야 합니다. 효과 칸이 어떻게 함께 동작하는지는 아래 [효과 칸](#효과-칸)에 있습니다.

### 기본

| 열 | 값 | 비우면 | 화면 |
|---|---|---|---|
| `ID` | 1~999의 정수. 시트 안에서 겹치면 안 됨. 1000 이상은 코드에 있는 서막 연습 기술(연습 베기 1001, 연습 내려치기 1002, 연습 막기 1003)이 쓰는 번호라 쓸 수 없음 | (필수) | 보이지 않음. 저장 파일과 코드가 기술을 찾는 번호. **바꾸지 마세요**(아래 [주의](#주의)) |
| `이름` | 글자 | (필수) | 기술이 나오는 모든 곳: 편성·커리큘럼 카드와 상세, 전투의 기술 설명·발동 배지·기록, 커리큘럼 과정 이름, 임무 안내 문구 |
| `구분` | `시작` / `획득` | (필수) | `시작`은 처음부터 가진 기술, `획득`은 커리큘럼 과정 또는 스테이지 첫 승리로 얻는 기술 |
| `열` | `Q` / `W` / `E` (소문자도 됨) | (필수) | 편성 열. Q 정공, W 강공, E 기교 검술 |
| `종류` | `공격` / `방어` | (필수) | 전투 판정(공격은 피해를 주고, 방어는 같은 칸 상대 공격을 줄임). 상세의 위력/방어 표시 |
| `속성` | `참격` / `타격` / `관통` / `방어` | (필수) | 상세의 공격 타입, 공격 동작(학생 그림), 상대의 `상대 속성 조건` 판정 대상. 방어 기술은 보통 `방어` |
| `ACT` | 0 이상의 정수 | (필수) | ACT 비용 |
| `최소 위력` / `최대 위력` | 0 이상의 정수, 최소 ≤ 최대 | (필수) | 위력 범위(방어 기술은 방어 수치). 연타는 **전체 합**이고 타수만큼 나눕니다 |
| `타수` | 1 이상의 정수 | (필수) | 공격 횟수. 2 이상이면 연타 |

| `설명` | 글자 | 빈칸 | **화면에 쓰이지 않음.** 기획 메모 |

## 값 목록

한글 이름은 정확히 적고, 영어 이름은 대소문자를 가리지 않습니다.

| 칸 | 쓸 수 있는 값 |
|---|---|
| `구분` | `시작`, `획득` |
| `열` | `Q`, `W`, `E` (소문자도 됨) |
| `종류`, `상대 종류 조건` | `공격`(Attack), `방어`(Defence). `대기`는 숨고르기 전용이라 쓸 수 없습니다 |
| `속성`, `상대 속성 조건` | `참격`(Slash), `타격`(Hit), `관통`(Penetrate), `방어`(Defence) |
| 기호 | `ACT`(Act), `검`(Sword), `방어`(Guard), `타수`(Hits), `회복`(Recovery), `후속`(Followup), `감소`(Reduction), `편차`(Variance) |
| 색 | `기본`(Neutral), `회복`(Recovery), `후속`(Followup), `감소`(Reduction), `고화력`(HighPower), `연타`(MultiHit), `편차`(Variance), `방어`(Defence) |

색은 의미 분류입니다. 실제 색과 기호 모양은 화면 코드가 정합니다. 지금 시트는 ACT·저항 회복에 `회복`, 위력 버프에 `후속`, 피해 감소에 `감소`, 방어 대응에 `방어`를 씁니다.

## 효과 칸

칸이 시작될 때 한 번, 이 순서로 적용됩니다.

1. `저항 회복`: 최대 저항의 N%를 회복합니다. 그 자체가 조건(저항이 줄어 있을 때만 실제로 회복)이라 상대 조건과 함께 쓸 수 없습니다.
2. 상대 조건(`상대 속성 조건` 또는 `상대 종류 조건` 중 하나): 같은 칸 상대 기술을 봅니다. 조건이 없으면 항상 통과합니다.
3. 조건을 통과하면 `저항 감소`와 `ACT 회복`을 적용합니다.
4. 버프(`위력 버프`·`보호 버프`·`버프 칸`)는 조건과 관계없이 줍니다. 자기 칸에는 걸리지 않고 뒤 칸부터 걸리며, 턴이 끝나면 사라집니다.

지금 시트의 예: 막기(7)는 `ACT 회복 2` + `상대 속성 조건 타격`, 기세 꺾기(5)는 `저항 감소 5` + `상대 종류 조건 공격`, 허점 노리기(6)는 `저항 감소 8` + `상대 종류 조건 방어`, 쳐내기(9)는 `위력 버프 20%` + `버프 칸 2`, 흘리기(8)는 `보호 버프 25%` + `버프 칸 1`입니다. 쿠페(42)는 `ACT 회복 3` + `저항 감소 20` + `상대 종류 조건 방어`, 플레슈(12)는 `ACT 회복 3` + `보호 버프 -50%` + `버프 칸 1`입니다. 탐색(43)은 `ACT 회복 1`로 다음 턴에 ACT를 더 받습니다. 몰아치기(44)는 `붕괴 대상 추가 피해 25%`로 이미 붕괴한 적에게 주는 각 타격의 체력 피해를 늘립니다. 한 타격이 저항을 0으로 만든 경우 그 타격은 보너스를 받지 않고, 이어지는 타격은 받을 수 있습니다.

조건부 버프, 기술 하나에 버프 여러 개, 적중·피격 때의 효과, 적이 받는 ACT 보상처럼 칸으로 적을 수 없는 효과는 프로그래머가 칸을 새로 만들어야 합니다(`SkillDefinitions.md`).

## 검사 규칙

시트를 읽을 때 모든 행을 검사하고, 문제를 **모두 모아** 한 번에 보여 줍니다. 문제마다 시트의 행 번호와 열 이름이 붙습니다. 문제가 하나라도 있으면 게임은 시트를 쓰지 않습니다.

**첫 행(열 이름)**

- 시트가 비어 있음: `1행: 시트가 비어 있습니다. 첫 행에 열 이름을 적으세요.`
- 파일이 UTF-8이 아님(Excel에서 그냥 `CSV(쉼표로 분리)`로 저장): `1행: 파일이 UTF-8이 아닙니다(한글이 깨져 읽힙니다). Excel에서 파일 → 다른 이름으로 저장 → CSV UTF-8(쉼표로 분리)로 다시 저장하세요.` 이때는 아래의 빠진 열 목록을 따로 보여 주지 않습니다.
- 필요한 열이 없음: `1행: 필요한 열이 없습니다: '버프 칸'. 첫 행의 열 이름은 띄어쓰기까지 똑같이 적어야 합니다 (…). 필요한 열: 'ID', '이름', …` (필요한 열 37개를 모두 적어 줍니다)
- 같은 열이 두 번: `1행: '이름' 열이 2번 있습니다. 같은 이름의 열은 하나만 둘 수 있습니다.`

열 이름에 문제가 있으면 나머지 행은 검사하지 않습니다.

**CSV 모양**

- `21행: 따옴표(")로 시작한 칸이 닫히지 않았습니다. 칸 안의 따옴표는 두 번("") 적으세요.`
- `21행: 따옴표로 감싼 칸이 닫힌 뒤에 쉼표 없이 글자가 이어집니다.`

Excel과 구글 시트는 따옴표를 알아서 처리하므로, 메모장으로 고칠 때만 신경 쓰면 됩니다.

**칸**

- 필수 칸이 빔: `7행 'ACT': 칸이 비어 있습니다. 꼭 적어야 하는 칸입니다.`
- 정수가 아니거나 너무 작음: `5행 'ACT': '1.5'은(는) 0 이상의 정수여야 합니다.` (`%`를 받는 칸이면 `(끝에 %를 붙여도 됩니다)`가 붙습니다)
- 연습 기술의 ID: `20행 'ID': '1001'은(는) 쓸 수 없습니다. 1000 이상은 코드에 있는 서막 연습 기술(연습 베기 등)이 쓰는 번호입니다. 1~999 중 쓰지 않는 번호를 적으세요.` 연습 기술도 ID로 효과와 문구를 찾으므로, 같은 ID의 행이 있으면 서막 상대의 연습 베기가 그 행의 효과를 쓰게 됩니다.
- 목록에 없는 값: `3행 '속성': '찌르기'은(는) 쓸 수 없습니다. 참격, 타격, 관통, 방어 중 하나를 적으세요.` (쓸 수 있는 값을 적어 줍니다)
- 대기 종류: `3행 '종류': '대기'은(는) 숨고르기 같은 공용 행동의 종류라 기술에 쓸 수 없습니다. 공격, 방어 중 하나를 적으세요.`
- 예/아니오가 아님: `3행 '고화력': 'maybe'은(는) 예/아니오로 읽을 수 없습니다. 예는 O, ○, TRUE, 1, 예, Y 중 하나, 아니오는 빈칸이나 X, FALSE, 0, 아니오, N 중 하나로 적으세요.`

**행** (ID를 읽었으면 `(ID n)`이 붙습니다)

- ID가 겹침: `11행 (ID 1) ID가 2행과 겹칩니다. ID는 기술마다 달라야 합니다.`
- 위력 범위: `2행 (ID 1) '최대 위력'(5)이(가) '최소 위력'(9)보다 작습니다.`
- 버프 칸만 있음: `4행 (ID 3) '버프 칸'이(가) 있으면 '위력 버프'나 '보호 버프'도 있어야 합니다.`
- 버프만 있음: `4행 (ID 3) '위력 버프'나 '보호 버프'를 쓰려면 '버프 칸'이(가) 1 이상이어야 합니다.`
- 두 조건을 함께 씀: `8행 (ID 7) 상대 조건은 '상대 속성 조건'과(와) '상대 종류 조건' 중 하나만 쓸 수 있습니다.`
- 저항 회복과 상대 조건: `19행 (ID 19) '저항 회복'은(는) 그 자체가 조건이라 상대 조건과 함께 쓸 수 없습니다.`
- 조건만 있고 걸 효과가 없음: `8행 (ID 7) 상대 조건은 ACT 회복이나 저항 감소가 있어야 합니다.`
- 공격이 아닌 기술의 태그: `14행 (ID 17) '고화력'과(와) '위력 편차'은(는) 공격에만 붙일 수 있습니다.`
- 방어 기술의 붕괴 추가 피해: `14행 (ID 17) '붕괴 대상 추가 피해'은(는) 공격 기술에만 쓸 수 있습니다.`
- 배지를 덜 적음: `2행 (ID 1) 배지 칸을 하나라도 쓰면 '배지 주 문구'과(와) '배지 요약'을(를) 모두 적어야 합니다.`

**시트 전체**

- `시작` 기술은 열마다 정확히 3개: `'구분'이(가) '시작'인 기술은 열마다 3개여야 합니다 (지금 Q 2개, W 4개, E 3개).` 편성 저장이 열마다 3개를 요구하고, 시작 편성이 곧 이 9개이기 때문입니다.
- `획득` 기술이 하나 이상: `'구분'이(가) '획득'인 기술이 하나도 없습니다. 커리큘럼이 줄 기술이 하나 이상 있어야 합니다.`

### 게임 코드와 맞추기

위 규칙을 모두 지킨 시트도 게임 코드가 기대하는 기술을 갖추지 않으면 나중에 게임이 멈추거나 커리큘럼·스테이지가 기술을 주지 못합니다. 그래서 시트 규칙에 문제가 없으면 코드와도 대조합니다(`CampaignSheetCheck`). 받아오기는 이 문제가 있으면 파일을 덮어쓰지 않고, `CSV 검사`·가져오기·Play 시작 때는 Console과 창에 빨간 오류로 보여 줍니다(시트는 그대로 읽힙니다).

- 커리큘럼 과정이 주는 기술이 없음: `ID 42 기술이 시트에 없습니다. 커리큘럼 과정 'quick-draw'이(가) 이 기술을 주므로 그 과정을 마치는 전투가 끝날 때 게임이 멈춥니다. ID를 바꾸거나 행을 지우지 마세요.`
- 커리큘럼 과정이 주는 기술이 `시작`: `ID 14 가로베기의 '구분'이(가) '시작'입니다. 커리큘럼 과정 'horizontal-cut'이(가) 주는 기술이라 '획득'이어야 합니다 (시작 기술이면 그 과정을 마쳐도 새로 얻는 기술이 없습니다).`
- 스테이지 첫 승리 보상 기술이 없거나 `시작`: 탐색(43)·몰아치기(44)는 `획득` 행이어야 합니다. 없으면 보상을 줄 때 멈추므로 받아오기를 막습니다.
- 코드가 쓰는 ID 1~9(적 행동·반격기, 서막·수련 임무와 안내 문구)가 없음: `ID 3 기술이 시트에 없습니다. 코드가 이 ID를 씁니다(스테이지 적의 행동·반격기, 서막·수련 임무와 그 안내 문구). 그 기술을 처음 쓰는 곳에서 게임이 멈추니 ID를 바꾸거나 행을 지우지 마세요.`

**경고(막지 않음)**: 받아오기와 `CSV 검사`는 `그림`이 1~17 밖인 기술을 `그림: …` 줄로 알립니다. 받아오기, `CSV 검사`, 가져오기, Play 시작은 커리큘럼 과정과 스테이지 첫 승리 보상 어느 쪽에도 없는 `획득` 기술을 `ID 50 새 베기: '구분'이(가) '획득'이지만 이 기술을 주는 커리큘럼 과정이 없어 게임에서 얻을 수 없습니다. …`로 알립니다. 새 기술은 행을 먼저 넣고 프로그래머가 지급 경로를 나중에 넣을 수 있으므로 막지 않습니다. 탐색·몰아치기는 스테이지 보상이므로 이 경고 대상이 아닙니다.

## 주의

### ID는 바꾸지 마세요

기술은 어디서나 ID로 찾습니다. ID를 바꾸거나 행을 지우면 그 ID를 쓰는 곳이 깨집니다.

| 쓰는 곳 | ID |
|---|---|
| 저장 파일의 편성(`lane 0 1 2 7` …)과 커리큘럼 진행 | 편성한 기술, 완료한 과정이 주는 기술 |
| 커리큘럼 과정이 주는 기술(`CampaignCurriculum.cs`) | 14, 15, 16, 42, 12, 21, 10, 17, 32, 19 |
| 스테이지 첫 승리가 주는 기술(`CampaignRun.cs`) | 1단계 43 탐색, 2단계 44 몰아치기 |
| 스테이지 적의 행동 | 1·2스테이지 1~6 순환, 3~8스테이지 리듬 1~9(`EnemyRhythms.md`) |
| 적 반격기(`CounterSystem.md`) | 5·6스테이지 7(막기), 7·8스테이지 4(정교한 찌르기) |
| 서막 임무(`PrologueMissions.md`) | 1, 2, 5, 7 |
| 수련 임무(`StoryUnlocks.md`) | Q 1·2·7, W 3·4·8, E 5·6·9 |
| 임무 안내 문구·커리큘럼 설명의 이름 토큰 | 1, 2, 3, 5, 7, 15, 16, 19, 21, 32, 42 |

위 표의 ID가 시트에 없거나 커리큘럼·스테이지가 주는 기술이 `시작`이면 받아오기가 막히고, `CSV 검사`·가져오기·Play 시작 때 오류가 뜹니다([게임 코드와 맞추기](#게임-코드와-맞추기)). 그래도 그 시트로 플레이하면, 그 기술을 처음 쓰는 곳(적 행동을 만들 때, 임무를 시작할 때, 그 기술을 주는 과정이나 스테이지를 마치는 전투가 끝날 때)에서 `기술 시트 'Assets/Game/Resources/Skills/skills.csv'에 ID 99 기술이 없습니다. 코드가 이 ID를 쓰니 ID를 바꾸거나 행을 지우지 마세요.` 오류로 멈춥니다. 지급 전투에서 멈추면 그 전투는 반영되지 않습니다(과정 완료·보상·저장 모두). 이름 토큰(`{기술:99}`)만 쓰는 곳은 멈추지 않고 화면에 `{기술:99?}`로 보입니다.

### 열을 바꾸면 저장이 깨집니다

저장 파일은 기술을 열마다 기억합니다. 편성된 기술의 `열`을 바꾸면 그 저장은 거부되고(예: E열에 편성한 플레슈(12)의 열을 W로 바꾸면 `기술 12은(는) 3번째 열에 편성할 수 없습니다.`), 타이틀에서 이어하기가 막힙니다(새 게임은 됨, `SaveSystem.md`). 시작 기술은 서막·수련 임무가 원래 열에 있다고 가정하고 안내 문구(`E를 짧게 누르거나 … 기세 꺾기를 예약하세요.`)도 그 열의 키를 말하므로, 시작 기술의 열은 바꾸지 마세요.

### 시작 기술

- 열마다 정확히 3개입니다. 새 시작 기술을 넣으려면 같은 열의 기존 하나를 `획득`으로 돌리거나 빼야 합니다(그 ID를 쓰는 곳은 위 표를 확인). `획득`으로 돌린 기술은 주는 커리큘럼 과정이 없어 경고가 납니다.
- 커리큘럼 과정이 주는 기술(위 표)을 `시작`으로 바꾸려면 프로그래머가 먼저 그 과정을 고쳐야 합니다. 그 전에는 받아오기가 막힙니다.
- 열마다 위에서 아래 순서가 새 게임의 기본 편성 순서이고, 저장이 없는 새 편성과 커리큘럼 초기화 뒤의 빈자리 채우기도 이 순서를 따릅니다.

### 그림

아이콘 그림은 1~17번까지 있습니다(`LegacyDuelArt.SkillIconCount = 17`). 1~15는 기존 아틀라스이고, 16·17은 개별 PNG입니다. `그림`을 비우면 ID와 같은 번호를 쓰므로, ID가 18 이상인 기술은 `그림`에 1~17 중 하나를 꼭 적어야 합니다. 없는 번호면 아이콘이 비어 보입니다. 지금 기본 기술 2 연속 베기는 11, 3 깊은 찌르기는 14를 쓰며, 획득 기술 14 가로베기 10, 15 사선베기 11, 16 알티바호 12, 17 호흡 13, 21 급소 찌르기 14, 32 유연함 15, 10 준비 3, 12 플레슈 1, 19 르프리즈 13, 42 쿠페 10, 43 탐색 16, 44 몰아치기 17을 씁니다. 탐색·몰아치기는 전용 그림을 사용합니다. 새 그림은 아트에 스프라이트를 추가하고 프로그래머가 개수를 올려야 합니다. 효과와 그림의 표식이 어긋나지 않는지도 확인하세요(`StarterSkillDesign.md`).

### 기술 이름은 시트에만

기술 이름은 시트의 `이름` 칸 한 곳에만 있습니다. 코드의 문구는 이름을 직접 쓰지 않고 `{기술:ID}` 토큰을 씁니다.

- `{기술:12}` → `플레슈`
- `{기술:12:을}` → `플레슈를` (받침에 맞춰 고릅니다. 을/를, 이/가, 은/는, 과/와, 으로/로, 이나/나, 이랑/랑 중 어느 쪽을 적어도 됩니다)
- 변하지 않는 조사는 토큰 뒤에 붙입니다: `{기술:12}의`
- 시트에 없는 ID는 화면에 `{기술:99?}`로 보입니다.

그래서 시트에서 이름을 바꾸면 커리큘럼 과정 이름·설명, 서막·수련 임무의 목표와 안내 문구가 다음 Play부터 함께 바뀝니다. 이름을 그대로 적는 곳은 연습 기술(연습 베기 등)과 숨고르기, 다이얼로그·컷신 텍스트(지금은 기술 이름이 없음), 그리고 `Docs`의 문서입니다.

### 테스트

EditMode·PlayMode 테스트는 지금 시트의 값(비용, 위력, 효과, 일부 화면 문구)을 많이 고정합니다. 값이나 이름을 바꾸면 테스트가 실패할 수 있습니다. 버그가 아니라 "바뀌었다"는 알림이니 프로그래머에게 알려 기대값을 함께 고칩니다.

## 새 기술 추가

1. 시트 아래쪽에 행을 하나 넣습니다. 새 ID(지금 쓰지 않는 번호), `구분` `획득`, 필수 칸, 효과 칸을 적습니다. ID가 16 이상이면 `그림`도 적습니다.
2. 받아오기(또는 Excel 저장) 뒤 문제가 없는지 확인합니다. 주는 과정이 아직 없다는 경고(`ID 50 새 베기: '구분'이(가) '획득'이지만 …`)는 정상입니다.
3. 프로그래머가 그 기술을 주는 커리큘럼 과정을 `CampaignCurriculum.cs`에 넣거나 스테이지 첫 승리 보상으로 `CampaignRun.cs`에 지정해야 얻을 수 있습니다(`Curriculum.md`, `CampaignLoop.md`). 어느 경로도 없는 `획득` 기술은 게임에서 얻을 수 없고 위 경고가 계속 뜹니다.

## 코드 (프로그래머용)

- `Runtime/LegacyCombat/LegacySkillSheet.cs`: 시트 읽기(`Parse`, 모든 문제를 모아 `SkillSheetException`), 쓰기(`Write`), 비교(`Describe`). 열 이름은 `LegacySkillSheet.Column`, 시트가 쓸 수 없는 ID의 시작은 `ReservedIdStart`(1000, 서막 연습 기술 1001~1003).
- `Runtime/Campaign/CampaignSheetCheck.cs`: 읽은 표를 게임 코드와 대조합니다. `Problems`(커리큘럼·스테이지 보상 기술이 없거나 `시작`, `CodeSkillIds` 1~9가 없음), `Warnings`(과정이나 스테이지 보상으로 얻을 수 없는 `획득` 기술). 넘겨받은 표만 읽습니다. 코드가 새 ID를 쓰기 시작하면 해당 지급 경로나 `CodeSkillIds`를 갱신합니다(`CampaignSheetCheckTests`가 실제 사용과 맞는지 검사).
- `Runtime/LegacyCombat/LegacySkillDefinitions.cs`: 기술 표. 처음 쓸 때 읽고(`Install`한 원본, 없으면 작업 폴더의 `SheetAssetPath`), `Skill(id)`·`Find(id)`로 찾습니다. 실패하면 `Install`/`Reload` 전까지 같은 오류를 다시 던집니다. 파일을 열지 못한 경우(`IOException`)만은 다음 접근에서 다시 읽습니다(`SkillDefinitions.md`).
- `Runtime/LegacyCombat/LegacySkillLabels.cs`: 속성·종류·기호·색의 한글 이름. `SkillInfoView`의 공격 타입도 여기서 읽습니다.

- `Runtime/Sheets/CsvTable.cs`, `SheetUrl.cs`, `SheetFile.cs`: CSV 읽기·쓰기, 구글 시트 주소 → CSV 주소, Excel이 열어 둔 파일도 읽는 파일 읽기(쓰기 공유를 허용하고 BOM을 뺍니다).
