# 선술집 실험

2026-10-22. 메인 화면의 **선술집 실험**에서 들어가는 별도 모드다. 상점·보관함·고정 8칸 편성에서 준비하고, AI 상대와 자동 전투한 뒤 다음 상점으로 돌아오는 사이클을 시험한다.

## 조작

1. 메인 화면에서 **선술집 실험**을 선택한다.
2. 상점의 기술을 선택해 설명을 보고 **구매**한다. 구매한 복사본은 보관함으로 들어간다.
3. 보관함에서 기술을 선택하고 **편성**을 누른다. 왼쪽의 첫 빈칸을 채운다.
4. 편성한 기술의 **판매**를 누르면 해당 자리만 숨고르기로 바뀐다. 뒤의 기술은 당겨지지 않는다. 보관함의 기술도 선택해 판매할 수 있다.
5. **전투 시작**을 누르면 편성한 8칸과 상대의 8칸이 자동으로 싸운다. 양쪽 배열을 같은 순서로 반복하며, 빈칸도 숨고르기로 실행한다. 전투 중에는 구매·판매·편성이나 수동 예약·스텝 입력을 받지 않는다.
6. 승리·패배·무승부 결과에서 **다음 라운드**를 누르면 자원을 지급받고 상점 3칸을 새로 채운다. 보관함과 편성은 유지한다. 패배해도 다음 라운드를 시험할 수 있다.
7. 전투 중 **편성으로** 또는 Esc는 싸움을 취소하고 같은 상점으로 돌아온다. 자원과 전적은 지급하지 않는다. 승패가 이미 정해진 마무리 연출 중에는 취소 대신 결과를 보여 준다.
8. 상점·결과에서 **타이틀로** 또는 Esc로 메인 화면에 돌아간다. 같은 실행 중 다시 들어오면 실험을 이어가며, 확인하지 않은 결과는 그대로 다시 보여 준다. **새 실험**은 상점에서 이 모드만 초기화한다.

편성한 기술의 자유 이동·회수는 제공하지 않는다. 판매로 만든 빈칸도 이후 일반 기술의 진입 위치가 된다. 전투용 순서를 읽으면 빈칸을 포함해 항상 8개이며 빈칸은 기존 숨고르기 기술이다. 같은 종류를 여러 장 사면 서로 다른 복사본으로 취급한다.

## 임시 경제

| 항목 | 규칙 |
|---|---|
| 상점 | 라운드마다 3장. 구매한 자리는 다음 라운드까지 비어 있다. 풀이 충분하면 한 상점의 세 종류는 서로 다르다. |
| 구매 | 종류와 무관하게 3자원. 자동 편성하지 않는다. |
| 판매 | 편성과 보관함 모두 복사본 1장당 1자원. |
| 지급 | 첫 라운드 3, 이후 4·5·6 순으로 증가하며 최대 10. 남은 자원을 이월하지 않고 새 지급량으로 교체한다. |
| 보관함 | 수량 제한 없음. 넘치는 카드는 가로 스크롤로 확인한다. |
| 기술 풀 | 현재 시트의 일반 시작·획득 기술. 적 전용, 반격 전용, 일회성, 숨고르기는 상점에서 제외한다. |

기술의 전투 ACT는 구매 가격과 별개다. 편성은 전투 시작 시 복사하므로 전투 효과가 상점의 카드나 원래 편성을 바꾸지 않는다. 자원 수치는 밸런스 확정값이 아니다.

## 임시 전투 규칙

- 양쪽 HP 60·저항 30으로 매 싸움을 새로 시작한다. 기존 결투 엔진의 기술 순서, 합·피해·저항 붕괴, 사용 효과, 카메라와 피격 연출을 재사용한다.
- 적은 현재 라운드에 맞춘 로컬 AI **선술집 도전자** 1명이다. 첫 라운드에는 기술 1개, 이후 2라운드마다 1개씩 늘려 최대 8개를 편성한다. 참격·관통·타격·방어를 섞고 남는 칸은 숨고르기로 채운다. 위력도 4라운드마다 1씩, 최대 3 증가한다. 상대의 기술 수는 상점에 표시한다.
- 한 싸움은 양쪽 8칸을 반복해 최대 **12턴** 진행한다. 어느 쪽도 쓰러지지 않으면 무승부다. 기록은 결과가 정해질 때 한 번만 반영하고, 자원은 결과에서 다음 라운드로 넘어갈 때만 지급한다.
- 이미 배치된 순서가 전투 입력이므로 ACT 소비·레인 회전·예약 시 자동 삽입/반환/제거 효과는 적용하지 않는다. 슬롯을 실행할 때의 기존 사용·강화·피해 효과는 적용한다. 붕괴 등으로 남은 기술이 취소돼도 다음 턴에는 원래 8칸을 다시 채운다.
- 현재는 수동 스텝과 맞물림을 끈다. 멀티 대전, 4인 체력·순위·탈락, 배치 전용 효과와 정식 상대 밸런스는 후속 범위다.

## 상태와 확장 경계

- `Runtime/Tavern/SkillTavernRun`이 라운드, 자원, 상점, 카드 복사본 ID, 보관함과 편성·전적을 소유한다. Unity와 캠페인 저장에 의존하지 않는다. 변경은 검사된 `TryBuy/TryDeploy/TrySellBoard/TrySellInventory/NextRound`를 통해 수행한다.
- `SkillTavernBattle`은 한 싸움의 편성 복사·상대·턴 상한·결과 1회 기록을 맡는다. `LegacyQueuedDuel.TrySetFixedQueues`로 준비된 양쪽 배열을 주입한 뒤 기존 엔진을 진행한다.
- `SkillTavernHud`와 `SkillTavernBattleHud`는 상태를 읽고 요청을 콜백으로 전달한다. `DuelPrototypeController.TrySkillTavernAction`이 상점·전투·결과의 허용 요청을 검사하고 로컬 실행을 맡는다. 화면에서 자원을 차감하거나 배치를 직접 바꾸지 않는다. 런타임 경제 모델의 `NextRound`는 모델 API이며 실제 화면에서는 완료 결과로만 진입을 허용한다.
- 향후 4인 방을 붙일 때 방의 권한 소유자가 같은 규칙을 실행하고 상태를 전달하는 경계로 사용할 수 있다. 방 관리, 준비 완료, 매칭, 상태 동기화, 연결 종료 처리와 네트워크 검증은 후속 작업이다. 현재 UI 요청 enum과 난수 시드는 네트워크 프로토콜을 약속하지 않는다.
- 캠페인 진행·보유 기술·경험치·보상·저장 파일과 분리한다. 전투 중에는 공유 화면의 세션을 잠시 교체하고, 편성이나 타이틀로 나올 때 원래 캠페인 세션을 돌려놓는다. 프로그램을 종료하면 실험 상태는 사라진다.

## 코드와 확인

중요 파일은 `SkillTavernRun.cs`, `SkillTavernBattle.cs`, `LegacyQueuedDuel.FixedQueues.cs`, `SkillTavernHud.cs`, `SkillTavernBattleHud.cs`, `DuelPrototypeController.SkillTavern.cs`, 기존 `TitleHud.cs`와 컨트롤러의 진입·복귀 연결이다. 새 씬·패키지·프리팹·Inspector 설정은 없다.

독립 EditMode 규칙 검사와 UI/진입 PlayMode 검사를 추가했다. 회사 PC에서는 Unity Editor를 실행하지 않는다. 컴파일·검사 결과와 실제 화면 확인 범위는 [Validation.md](Validation.md)에 기록한다.
