# 선술집 실험

2026-10-22. 메인 화면의 **선술집 실험**에서 들어가는 별도 모드다. 상점·보관함·고정 8칸 편성에서 준비하고, AI 상대와 **한 턴만** 자동 전투한 뒤 다음 상점으로 돌아오는 사이클을 시험한다. 상점은 전투 화면을 덮는 별도 전체 화면이며, 양쪽의 남은 HP·저항을 표시한다.

## 조작

1. 메인 화면에서 **선술집 실험**을 선택한다.
2. 상점의 기술을 선택해 설명을 보고 **편성 3** 또는 **보관 3**을 누른다. 두 동작 모두 3자원을 지불한다. 편성은 왼쪽의 첫 빈칸에 바로 넣고, 보관은 보관함에 넣는다. 편성이 가득 차면 보관만 가능하다.
3. 보관함에서 기술을 선택하고 **편성**을 누르면 추가 비용 없이 왼쪽의 첫 빈칸을 채운다.
4. 편성한 기술의 **판매**를 누르면 해당 자리만 숨고르기로 바뀐다. 뒤의 기술은 당겨지지 않는다. 보관함의 기술도 선택해 판매할 수 있다.
5. **8칸 실행**을 누르면 편성한 8칸과 상대의 8칸이 한 턴 자동으로 싸운다. 빈칸도 숨고르기로 실행한다. 전투 중에는 구매·판매·편성이나 수동 예약·스텝 입력을 받지 않는다.
6. 양쪽이 살아 있으면 턴 종료 후 **자동으로 다음 라운드 상점**이 열린다. 보관함·편성·양쪽 HP·저항·지속 전투 상태를 유지하고, 새 자원과 상점 3칸을 받는다. 기술을 추가·판매한 뒤 다시 8칸을 실행한다.
7. 전투 중 **편성으로** 또는 Esc는 진행 중인 턴을 취소하고 시작 전 상점 상태로 돌아온다. 전투에서 바뀐 HP·저항 등도 되돌리고 자원을 추가 지급하지 않는다. 이미 한 턴을 완료했다면 정상적으로 다음 상점을 열며, 승패가 정해졌다면 결과를 보여 준다.
8. 어느 쪽이 쓰러지거나 24턴이 끝나면 승리·패배·무승부 결과를 보여 준다. **새 실험**으로 처음부터 다시 시작할 수 있다.
9. 상점·결과에서 **타이틀로** 또는 Esc로 메인 화면에 돌아간다. 같은 실행 중 다시 들어오면 실험을 이어가며, 확인하지 않은 결과는 그대로 다시 보여 준다. **새 실험**은 이 모드의 편성·보관함·자원·전투 상태를 초기화한다.

편성한 기술의 자유 이동·회수는 제공하지 않는다. 판매로 만든 빈칸도 이후 일반 기술의 진입 위치가 된다. 전투용 순서를 읽으면 빈칸을 포함해 항상 8개이며 빈칸은 기존 숨고르기 기술이다. 같은 종류를 여러 장 사면 서로 다른 복사본으로 취급한다.

상점의 **새로고침 1**을 누르면 1자원을 쓰고 상점 3칸을 모두 다시 뽑는다. 구매해서 빈 칸도 다시 채워지며, 같은 기술이 재등장할 수 있다. 같은 라운드에 여러 번 사용할 수 있고 자원이 없으면 사용할 수 없다. 라운드·지급량·편성·보관함·전투 상태는 그대로 유지한다.

## 임시 경제

| 항목 | 규칙 |
|---|---|
| 상점 | 라운드마다 3장. 구매한 자리는 다음 라운드 또는 새로고침까지 비어 있다. 풀이 충분하면 한 상점의 세 종류는 서로 다르다. |
| 새로고침 | 1자원. 현재 상점 3칸을 모두 다시 뽑는다. 같은 기술 재등장 가능. 라운드·지급량은 변하지 않으며 자원이 있는 만큼 반복할 수 있다. |
| 편성 구매 | 종류와 무관하게 3자원. 왼쪽의 첫 빈칸에 즉시 편성한다. 빈칸이 없으면 자원을 쓰거나 상품을 소모하지 않는다. |
| 보관 구매 | 종류와 무관하게 3자원. 보관함에 넣고, 이후 편성은 무료다. |
| 판매 | 편성과 보관함 모두 복사본 1장당 1자원. |
| 지급 | 첫 라운드 3. 한 턴을 완료하고 다음 상점에 올 때마다 4·5·6 순으로 1씩 증가하며 최대 10. 사용하지 않은 자원은 사라지고 새 지급량으로 교체한다. 같은 상점 재진입·진행 중인 턴 취소로는 지급하지 않는다. |
| 보관함 | 수량 제한 없음. 넘치는 카드는 가로 스크롤로 확인한다. |
| 기술 풀 | 현재 시트의 일반 시작·획득 기술. 적 전용, 반격 전용, 일회성, 숨고르기는 상점에서 제외한다. |

기술의 전투 ACT는 구매 가격과 별개다. 편성은 매 턴 시작 시 복사하므로 전투 효과가 상점의 카드나 원래 편성을 바꾸지 않는다. 자원 수치는 밸런스 확정값이 아니다.

## 임시 전투 규칙

- 새 실험의 전투는 양쪽 HP 500·저항 30으로 시작한다. 상점을 오갈 때 같은 전투를 이어가며 HP·저항을 초기화하지 않는다. 상점에 표시한 턴 종료 상태는 다음 8칸 실행 전까지 유지하고, 기존 턴 경계의 회복·상태 처리는 다음 턴을 시작할 때 한 번 수행한다. 기존 결투 엔진의 기술 순서, 합·피해·저항 붕괴, 사용 효과, 카메라와 피격 연출을 재사용한다.
- 적은 현재 라운드에 맞춘 로컬 AI **선술집 도전자** 1명이다. 첫 라운드에는 기술 1개, 이후 2라운드마다 1개씩 늘려 최대 8개를 편성한다. 참격·관통·타격·방어를 섞고 남는 칸은 숨고르기로 채운다. 위력도 4라운드마다 1씩, 최대 3 증가한다. 상대의 기술 수는 상점에 표시한다.
- 상점 한 라운드는 양쪽 8칸을 한 번 실행한다. 완료할 때마다 다음 상점으로 돌아오고, 같은 전투를 최대 **24턴** 이어간다. 어느 쪽도 쓰러지지 않으면 무승부다. 전적은 최종 결과가 정해질 때 한 번만 반영하며, 최종 결과에서는 다음 라운드 자원을 지급하지 않는다.
- 이미 배치된 순서가 전투 입력이므로 ACT 소비·레인 회전·예약 시 자동 삽입/반환/제거 효과는 적용하지 않는다. 슬롯을 실행할 때의 기존 사용·강화·피해 효과는 적용한다. 붕괴 등으로 남은 기술이 취소돼도 다음 턴에는 원래 8칸을 다시 채운다.
- 현재는 수동 스텝과 맞물림을 끈다. 멀티 대전, 4인 체력·순위·탈락, 배치 전용 효과와 정식 상대 밸런스는 후속 범위다.

## 상태와 확장 경계

- `Runtime/Tavern/SkillTavernRun`이 라운드, 자원, 상점, 카드 복사본 ID, 보관함과 편성·전적을 소유한다. Unity와 캠페인 저장에 의존하지 않는다. 변경은 검사된 `TryBuy/TryBuyAndDeploy/TryRefreshShop/TryDeploy/TrySellBoard/TrySellInventory/NextRound`를 통해 수행한다. 유료 새로고침과 턴 완료의 상점 추첨은 같은 추첨 규칙을 쓰며, 자원 부족으로 거부한 새로고침은 난수를 소비하지 않는다.
- `SkillTavernBattle`은 지속 전투와 각 턴의 편성 복사·상대·턴 상한·결과 1회 기록을 맡는다. `TryStartTurn`에서 준비된 양쪽 배열을 `LegacyQueuedDuel.TrySetFixedQueues`로 주입하고, `TryCompleteTurn`이 완료된 턴을 한 번만 정산한다. 정상 상점 복귀는 같은 Duel을 유지한다. 진행 중인 턴 취소 시에만 원래 시드와 완료한 배열 기록을 재생해 이전 상점 상태·다음 난수를 복원한다. 공용 엔진과 난수 코드는 바꾸지 않는다.
- `SkillTavernHud`와 `SkillTavernBattleHud`는 상태를 읽고 요청을 콜백으로 전달한다. `DuelPrototypeController.TrySkillTavernAction`이 상점·전투·결과의 허용 요청을 검사하고 로컬 실행을 맡는다. 화면에서 자원을 차감하거나 배치를 직접 바꾸지 않는다. 런타임 경제 모델의 `NextRound`는 모델 API이며 화면의 다음 라운드 요청은 거부하고 완료된 턴을 통해서만 진입한다.
- 향후 4인 방을 붙일 때 방의 권한 소유자가 같은 규칙을 실행하고 상태를 전달하는 경계로 사용할 수 있다. 방 관리, 준비 완료, 매칭, 상태 동기화, 연결 종료 처리와 네트워크 검증은 후속 작업이다. 현재 UI 요청 enum과 난수 시드는 네트워크 프로토콜을 약속하지 않는다.
- 캠페인 진행·보유 기술·경험치·보상·저장 파일과 분리한다. 전투 중에는 공유 화면의 세션을 잠시 교체하고, 편성이나 타이틀로 나올 때 원래 캠페인 세션을 돌려놓는다. 프로그램을 종료하면 실험 상태는 사라진다.

## 코드와 확인

중요 파일은 `SkillTavernRun.cs`, `SkillTavernBattle.cs`, `LegacyQueuedDuel.FixedQueues.cs`, `SkillTavernHud.cs`, `SkillTavernBattleHud.cs`, `DuelPrototypeController.SkillTavern.cs`, 기존 `TitleHud.cs`와 컨트롤러의 진입·복귀 연결이다. 새 씬·패키지·프리팹·Inspector 설정은 없다.

독립 EditMode 규칙 검사와 UI/진입 PlayMode 검사를 추가했다. 회사 PC에서는 Unity Editor를 실행하지 않는다. 컴파일·검사 결과와 실제 화면 확인 범위는 [Validation.md](Validation.md)에 기록한다.
